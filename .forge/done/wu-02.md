# Add config file parser

## Outcome

Herald can load and validate a YAML configuration file that defines apps (git-based auto-deploy services) and stacks (managed infrastructure services). Running `herald status` with a valid config file prints the parsed service names and domains. Running with an invalid config file prints a clear validation error and exits with code 1.

## Values

1. Correctness — invalid configs must be rejected with actionable error messages, never silently accepted.
2. Extensibility — the config struct must support future additions (preview config, secrets references) without breaking existing configs.
3. Clarity — config field names must be self-documenting. No abbreviations that require reading docs.

## Context

- `main.go` — entry point, calls `cmd.Execute()`.
- `cmd/root.go` — root Cobra command with `--config` flag (default `/etc/herald/config.yml`). The config path is available to all subcommands.
- `cmd/status.go` — stub that currently prints "not implemented". This WU makes it print parsed config.
- Herald is a deployment daemon. The config file defines what runs on this server. Two categories:
  - **Apps**: your code, deployed from GitHub repos via webhooks. Same repo can appear multiple times with different configs (different env, mounts, domains).
  - **Stacks**: infrastructure services (nextcloud, ghost) whose compose files live in the server's IaC repo. Manually triggered updates with scripted runbooks.
- Secrets are NOT stored in the config file. The config references secret keys that are resolved at deploy time from an encrypted secrets store (implemented in wu-03).
- Environment variables in string values should support `${VAR}` syntax for expansion from the process environment, but only for the `github_token` field in the server section. App env vars are handled differently (env_file + secrets store).

## Creates

- `internal/config/config.go` — config types and loader.
- `internal/config/config_test.go` — unit tests for parsing and validation.
- `internal/config/testdata/valid.yml` — test fixture: valid config.
- `internal/config/testdata/invalid_missing_domain.yml` — test fixture: app missing domain.
- `internal/config/testdata/invalid_duplicate_domain.yml` — test fixture: two services with same domain.

## Modifies

- `cmd/root.go` — load config in PersistentPreRunE, store in a package-level variable accessible to subcommands.
- `cmd/status.go` — print parsed service names and domains instead of "not implemented".

## Requirements

### 1. Config file format

The config file is YAML. Top-level structure:

```yaml
server:
  name: srv2                              # human-readable server name
  deploy_domain: deploy.example.com       # domain where herald webhook listens
  stacks_dir: /opt/deploy                 # base directory for app deployments
  github_token: ${GITHUB_TOKEN}           # expanded from env at load time

apps:
  budget:
    repo: nogo/budget-app                 # GitHub owner/repo
    branch: main                          # branch to track
    domain: budget.example.com            # primary domain
    env_file: .env.budget                 # relative to stacks_dir, on server only
    compose: compose.yml                  # compose file name in the repo (default: compose.yml)
    override: |                           # inline compose override YAML (optional)
      services:
        app:
          volumes:
            - /srv/budget/data:/data
    secrets:                              # optional, references to secrets store
      - key: budget/db_password
        type: env                         # "env" or "docker-secret"
        target: DB_PASSWORD               # env var name or secret name
    preview:                              # optional, preview deploy config
      enabled: false
      domain: "*.preview.example.com"

  tracker:
    repo: nogo/budget-app                 # same repo as budget — valid
    branch: main
    domain: tracker.example.com
    env_file: .env.tracker
    override: |
      services:
        app:
          volumes:
            - /srv/tracker/data:/data

stacks:
  nextcloud:
    path: stacks/nextcloud                # path in the server IaC repo
    domain: cloud.example.com
    auto_deploy: false                    # true = deploy on IaC repo push
    update_script: stacks/nextcloud/update.sh

  ghost:
    path: stacks/ghost
    domain: blog.example.com
    auto_deploy: false
    update_script: stacks/ghost/update.sh
```

### 2. Go types

Define the following structs in `internal/config/config.go`:

- `Config` — top-level: `Server`, `Apps map[string]App`, `Stacks map[string]Stack`
- `Server` — `Name`, `DeployDomain`, `StacksDir`, `GithubToken`
- `App` — `Repo`, `Branch`, `Domain`, `EnvFile`, `Compose`, `Override`, `Secrets []SecretRef`, `Preview *PreviewConfig`
- `Stack` — `Path`, `Domain`, `AutoDeploy`, `UpdateScript`
- `SecretRef` — `Key`, `Type` (enum: "env", "docker-secret"), `Target`
- `PreviewConfig` — `Enabled`, `Domain`

All fields should have `yaml` struct tags. Optional fields use pointer types. Use `omitzero` tag (Go 1.24+) for JSON serialization of optional zero-value fields — note: for YAML parsing with `gopkg.in/yaml.v3`, `omitempty` is still used in yaml tags, but any JSON output of these structs should use `omitzero`. Use `new(value)` (Go 1.26) for pointer field initialization in tests and defaults, e.g., `Preview: new(PreviewConfig{Enabled: true, Domain: "*.preview.basalt.solutions"})`.

### 3. Loader function

`func Load(path string) (*Config, error)` — reads the YAML file, unmarshals into `Config`, runs validation, expands `${VAR}` in `Server.GithubToken` from `os.Getenv`. Returns a descriptive error on failure.

### 4. Validation rules

The `Load` function must validate:

- `server.name` is required and non-empty.
- `server.deploy_domain` is required and non-empty.
- `server.stacks_dir` is required and non-empty.
- Every app must have `repo`, `branch`, and `domain` set.
- Every stack must have `path` and `domain` set.
- No two services (apps + stacks combined) may share the same `domain`.
- `App.Compose` defaults to `compose.yml` if not set.
- `App.Branch` defaults to `main` if not set.
- `SecretRef.Type` must be either `"env"` or `"docker-secret"`.
- If `preview.enabled` is true, `preview.domain` must be set and contain a `*` wildcard.

Validation errors must include the service name and field that failed. Example: `"app 'budget': domain is required"`.

### 5. Status command update

`herald status` loads the config and prints a table:

```
Server: srv2
Deploy: deploy.example.com

Apps:
  budget         budget.example.com          nogo/budget-app:main
  tracker         tracker.example.com          nogo/budget-app:main

Stacks:
  nextcloud      cloud.example.com             auto:no
  ghost          blog.example.com      auto:no
```

### 6. Config loading in root command

In `cmd/root.go`, add a `PersistentPreRunE` that loads the config file from the `--config` flag path. Store the result in a package-level `var Cfg *config.Config`. Subcommands that need config access it via `cmd.Cfg`. Commands that don't need config (`version`) should skip loading — use a Cobra annotation or check the command name.

## Constraints

- `go build ./...` must pass.
- `go vet ./...` must pass.
- `go test ./...` must pass — including the new config tests.
- Use `gopkg.in/yaml.v3` for YAML parsing. Add it as a dependency.
- Do not parse or resolve secrets — that's wu-03's job. The config just stores the `SecretRef` structs.
- Do not interact with Docker, Caddy, GitHub, or the filesystem beyond reading the config file.

## Failure Modes

- **YAML parsing error with no context**: User gets "yaml: unmarshal error" with no indication which field. Mitigation: wrap yaml errors with the file path and use `yaml.v3`'s error position info. Use `errors.AsType[*yaml.TypeError](err)` (Go 1.26) for typed error handling.
- **Env var not set for github_token**: `${GITHUB_TOKEN}` expands to empty string silently. Detection: if the expanded value is empty and the original contained `${`, log a warning via `slog.Warn`.
- **Two apps with same domain accepted**: Would cause routing conflicts in Caddy. Detection: validation rejects duplicate domains across all services. Use `slices.Collect` and iterator patterns from Go 1.23+ for domain collection and deduplication where appropriate.

## Verification

```bash
go build ./...
go vet ./...
go test ./internal/config/...
./herald --config internal/config/testdata/valid.yml status
./herald --config internal/config/testdata/invalid_missing_domain.yml status 2>&1 | grep "domain is required"
```
