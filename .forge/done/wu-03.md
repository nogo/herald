# Add age-encrypted secrets store

## Outcome

Running `herald secret set myapp/db_password "s3cret"` encrypts and stores the secret. Running `herald secret get myapp/db_password` decrypts and prints `s3cret`. Running `herald secret list` shows `myapp/db_password`. Running `herald secret import myapp/cert /path/to/cert.pem` reads the file and stores its contents as a secret. All secrets are stored in a single age-encrypted file on disk. A master age key is generated on first use if it doesn't exist.

## Values

1. Security — secrets must never be written to disk unencrypted (except transiently in memory). The age key file must have 0600 permissions.
2. Simplicity — one encrypted file, one key file. No key management infrastructure.
3. Reliability — corrupted or missing secrets file produces a clear error, not a panic or silent failure.

## Context

- `cmd/secret.go` — stub Cobra command with `set`, `get`, `list`, `import` subcommands. Currently prints "not implemented".
- `cmd/root.go` — root command with `--config` flag. The config (from wu-02) has `server.stacks_dir` which determines where the secrets file lives.
- `internal/config/config.go` — config types. `SecretRef` struct defines how apps reference secrets: `Key`, `Type` ("env" or "docker-secret"), `Target`.
- Herald uses age encryption (https://age-encryption.org/). The Go library is `filippo.io/age`.
- The secrets store file is `secrets.age` in the herald data directory (`/etc/herald/` by default).
- The age key file is `/etc/herald/age.key`.
- The secrets store is NOT committed to git. It exists only on the server.

## Creates

- `internal/secrets/store.go` — secrets store implementation.
- `internal/secrets/store_test.go` — unit tests.

## Modifies

## Requirements

### 1. Secrets store interface

```go
type Store struct {
    keyPath     string // path to age.key
    secretsPath string // path to secrets.age
}

func NewStore(dataDir string) *Store
func (s *Store) Init() error                        // generate age key if missing
func (s *Store) Set(key, value string) error        // add/update a secret
func (s *Store) Get(key string) (string, error)     // retrieve a secret
func (s *Store) List() ([]string, error)            // list all secret keys
func (s *Store) Delete(key string) error            // remove a secret
func (s *Store) Import(key, filePath string) error  // read file, store as secret
func (s *Store) Resolve(refs []config.SecretRef) (envVars map[string]string, dockerSecrets map[string]string, error)
```

### 2. Storage format

Internally, secrets are stored as a JSON object `map[string]string` (key → value). This JSON is encrypted with age and written to `secrets.age`. On every write operation:

1. Decrypt the existing file (or start with empty map if file doesn't exist).
2. Modify the map.
3. Re-encrypt the entire map and write atomically (write to temp file, rename).

This is not efficient for large stores but is simple and correct. Herald will have at most dozens of secrets, not thousands.

### 3. Age key management

- `Init()` checks if `age.key` exists. If not, generates a new age X25519 identity and writes it to `keyPath` with permissions `0600`.
- The key file contains one line: the age secret key (starts with `AGE-SECRET-KEY-1...`).
- The corresponding public key (recipient) is derived from the secret key at runtime.
- If `age.key` exists but is unreadable (permissions, corrupt), return a clear error.

### 4. Encryption/decryption

- Use `filippo.io/age` for all crypto operations.
- Encrypt: marshal the secrets map to JSON, encrypt with the age public key (derived from the identity), write to `secrets.age`.
- Decrypt: read `secrets.age`, decrypt with the age identity, unmarshal JSON.
- If `secrets.age` doesn't exist, treat as empty store (no error on read, create on first write).
- If `secrets.age` exists but can't be decrypted (wrong key, corrupt), return error: `"cannot decrypt secrets store: <reason>. Is the age key correct?"`.

### 5. Atomic writes

Always write the secrets file atomically: write to `secrets.age.tmp` in the same directory, then `os.Rename` to `secrets.age`. This prevents corruption if the process is killed mid-write.

### 6. Resolve function

`Resolve(refs []config.SecretRef)` takes a list of secret references from the config and returns two maps:

- `envVars`: for refs with `Type == "env"`, maps `Target` → decrypted value. These will be passed as environment variables to Docker Compose.
- `dockerSecrets`: for refs with `Type == "docker-secret"`, maps `Target` → decrypted value. These will be written to temp files and mounted as Docker secrets.

If a referenced key doesn't exist in the store, return error: `"secret 'myapp/db_password' not found in store"`.

### 7. CLI commands

**`herald secret set <key> <value>`**
- Sets the secret. If the key exists, overwrites.
- Calls `store.Init()` first (creates age key if needed).
- Prints: `secret 'myapp/db_password' set`.

**`herald secret get <key>`**
- Prints the decrypted value to stdout (no newline suffix, for piping).
- Exits with code 1 if key not found.

**`herald secret list`**
- Prints one key per line, sorted alphabetically.
- Prints nothing if no secrets exist.

**`herald secret import <key> <file>`**
- Reads the file contents and stores as the secret value.
- Useful for certificates, Docker secret files, multi-line values.
- Prints: `secret 'myapp/cert' imported from /path/to/cert.pem (1234 bytes)`.

**`herald secret delete <key>`**
- Removes the secret.
- Prints: `secret 'myapp/db_password' deleted`.
- Exits with code 1 if key not found.

### 8. Data directory flag

Add `--data-dir` persistent flag to the root command (default `/etc/herald/`). This controls where `age.key` and `secrets.age` are stored. Pass this to the secrets store constructor.

## Constraints

- `go build ./...` must pass.
- `go test ./...` must pass.
- Use `filippo.io/age` for encryption. No other crypto libraries.
- Secret values must never be logged, even in verbose mode. Log the key name only.
- The age key file must have `0600` permissions. If it doesn't, `Init()` should fix it and log a warning.
- The secrets file must have `0600` permissions.
- Do not implement any Docker integration — the `Resolve` function returns maps, the caller (wu-05) will use them.

## Failure Modes

- **Age key deleted while secrets exist**: Secrets become unrecoverable. Detection: `Get` returns decryption error. Mitigation: `Init()` never overwrites an existing key. Warn user to back up `age.key`.
- **Concurrent writes corrupt secrets file**: Two `herald secret set` calls at the same time. Mitigation: use file locking (`syscall.Flock`) on the secrets file during write operations.
- **Go 1.26 note**: Use `crypto/rand.Text` (Go 1.24+) to generate random strings where needed (e.g., if auto-generating a webhook secret). Use `os.OpenRoot` (Go 1.24+) to scope file operations to the data directory for security. Use `errors.AsType[T]` for typed error handling.
- **Secret value contains special characters**: JSON encoding handles this. Test with values containing quotes, newlines, binary data.
- **Secrets file grows unbounded**: Unlikely with dozens of secrets. Not a concern at this scale.

## Verification

```bash
go build ./...
go test ./internal/secrets/...

# Integration test (manual):
export HERALD_DATA_DIR=$(mktemp -d)
./herald --data-dir "$HERALD_DATA_DIR" secret set test/password "hello123"
./herald --data-dir "$HERALD_DATA_DIR" secret get test/password  # prints hello123
./herald --data-dir "$HERALD_DATA_DIR" secret list               # prints test/password
echo "cert-content" > /tmp/test.pem
./herald --data-dir "$HERALD_DATA_DIR" secret import test/cert /tmp/test.pem
./herald --data-dir "$HERALD_DATA_DIR" secret delete test/password
./herald --data-dir "$HERALD_DATA_DIR" secret list               # prints test/cert only
ls -la "$HERALD_DATA_DIR"/age.key    # should be -rw------- (0600)
ls -la "$HERALD_DATA_DIR"/secrets.age # should be -rw------- (0600)
rm -rf "$HERALD_DATA_DIR"
```
