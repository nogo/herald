# Add GitHub webhook auto-registration

## Outcome

When herald processes a config file containing app definitions, it automatically registers GitHub webhooks on each referenced repository. Running `herald webhooks sync` registers missing webhooks and removes stale ones. Running `herald webhooks list` shows all registered webhooks and their status. Adding a new app to the config and running `herald webhooks sync` automatically creates the webhook on the new repo. Removing an app and syncing removes the webhook.

## Values

1. Automation — adding an app to the config should be sufficient. No manual GitHub settings.
2. Idempotency — running sync multiple times must not create duplicate webhooks.
3. Security — each webhook gets its own HMAC secret, or shares the global `herald/webhook_secret`. Secrets are never exposed in logs or API responses.

## Context

- `internal/config/config.go` — `Config.Server.GithubToken` is the GitHub API token (expanded from `${GITHUB_TOKEN}` env var). `Config.Apps` maps app names to `App` structs with `Repo` field (format: `owner/repo`).
- `internal/secrets/store.go` — secrets store. The webhook HMAC secret is stored at `herald/webhook_secret`.
- `internal/webhook/server.go` — webhook HTTP server listens on the configured port. The webhook URL is `https://<deploy_domain>/webhook`.
- GitHub's webhook API: `POST /repos/{owner}/{repo}/hooks` to create, `GET /repos/{owner}/{repo}/hooks` to list, `DELETE /repos/{owner}/{repo}/hooks/{id}` to delete. Requires a token with `admin:repo_hook` scope (or `repo` scope for private repos).
- Multiple apps may reference the same repo (budget and tracker both use `nogo/budget-app`). Only ONE webhook should be registered per unique repo, not per app.

## Creates

- `internal/github/webhooks.go` — GitHub webhook management via REST API.
- `internal/github/webhooks_test.go` — unit tests with HTTP mocks.
- `cmd/webhooks.go` — `herald webhooks` command with `sync`, `list` subcommands.

## Modifies

- `cmd/root.go` — add `webhooks` to available commands.

## Requirements

### 1. GitHub API client

Create a minimal GitHub API client (no third-party library — use `net/http` + `encoding/json`):

```go
type GitHubClient struct {
    Token   string
    BaseURL string  // default: "https://api.github.com"
    HTTP    *http.Client
    Logger  *slog.Logger
}

func NewGitHubClient(token string, logger *slog.Logger) *GitHubClient
```

Requests must include:
- `Authorization: Bearer <token>` header
- `Accept: application/vnd.github+json` header
- `User-Agent: herald/<version>` header

Handle rate limiting: if GitHub returns HTTP 403 with `X-RateLimit-Remaining: 0`, log a warning with the reset time from `X-RateLimit-Reset` header and return a descriptive error.

**Go 1.26 idioms**: Use `errors.AsType[*GitHubError](err)` for typed error handling of API errors. Use `slices.Collect` with iterators to deduplicate repos from config. Use `maps.Keys` to iterate over config app entries.

### 2. Webhook CRUD operations

```go
// List webhooks for a repo
func (c *GitHubClient) ListWebhooks(ctx context.Context, owner, repo string) ([]Webhook, error)

// Create a webhook
func (c *GitHubClient) CreateWebhook(ctx context.Context, owner, repo string, req CreateWebhookRequest) (*Webhook, error)

// Delete a webhook by ID
func (c *GitHubClient) DeleteWebhook(ctx context.Context, owner, repo string, id int64) error

type Webhook struct {
    ID     int64    `json:"id"`
    Active bool     `json:"active"`
    Config WHConfig `json:"config"`
    Events []string `json:"events"`
    URL    string   // extracted from config
}

type WHConfig struct {
    URL         string `json:"url"`
    ContentType string `json:"content_type"`
    Secret      string `json:"secret,omitempty"`  // only set on create, never returned by API
    InsecureSSL string `json:"insecure_ssl"`
}

type CreateWebhookRequest struct {
    URL    string
    Secret string
    Events []string  // ["push", "pull_request"]
}
```

### 3. Webhook sync logic

`SyncWebhooks(ctx, config, secretStore)`:

1. Collect all unique repos from `config.Apps` (deduplicate — budget and tracker both reference `nogo/budget-app`, count as one).
2. Also include the server IaC repo if it's configured (for self-update triggers).
3. For each unique repo:
   a. List existing webhooks via GitHub API.
   b. Check if a webhook already exists with URL matching `https://<deploy_domain>/webhook`.
   c. If it exists and is active: skip (already synced).
   d. If it exists but is inactive: delete and recreate.
   e. If it doesn't exist: create it.
4. For repos that have webhooks pointing to this herald instance but are no longer in the config: delete the webhook.

Webhook creation payload:
```json
{
  "name": "web",
  "active": true,
  "events": ["push", "pull_request"],
  "config": {
    "url": "https://deploy.example.com/webhook",
    "content_type": "json",
    "secret": "<webhook-secret-from-store>",
    "insecure_ssl": "0"
  }
}
```

### 4. Webhook identification

To identify webhooks managed by herald (vs. manually created ones), match on the webhook URL. Herald's webhooks always point to `https://<deploy_domain>/webhook`. Only manage webhooks with this URL — leave all others untouched.

### 5. Events configuration

Determine which events to subscribe to based on app config:

- If ANY app referencing this repo has `preview.enabled: true`: subscribe to `["push", "pull_request"]`.
- Otherwise: subscribe to `["push"]` only.

### 6. CLI commands

**`herald webhooks sync`**:
1. Loads config and secrets.
2. Runs the sync logic.
3. Prints a summary:
   ```
   Webhooks synced:
     nogo/budget-app    ✓ exists (id: 12345)
     nogo/sidenote      + created (id: 12346)
     nogo/old-app       - removed (id: 12340)
   ```

**`herald webhooks list`**:
1. For each unique repo in config, lists the webhook status:
   ```
   Repo                  Webhook URL                              Status
   nogo/budget-app       https://deploy.example.com/webhook       active
   nogo/sidenote         https://deploy.example.com/webhook       active
   nogo/invest           -                                        not registered
   ```

### 7. Error handling

- **No GitHub token**: If `config.Server.GithubToken` is empty, print error: `"GitHub token not configured. Set GITHUB_TOKEN environment variable."` and exit 1.
- **Insufficient permissions**: If the API returns 404 for webhook operations (GitHub returns 404 instead of 403 for permission errors on repos), print: `"Cannot manage webhooks for 'nogo/budget-app'. Ensure the token has 'admin:repo_hook' scope and access to this repository."`.
- **Repo doesn't exist**: Print error and continue with other repos. Don't fail the entire sync.

## Constraints

- `go build ./...` must pass.
- `go test ./...` must pass.
- Use only Go standard library for HTTP. No `go-github` or similar libraries.
- Never log or print the webhook secret or GitHub token.
- Do not modify webhooks on repos not referenced in the config.
- Only manage webhooks with URLs matching herald's deploy domain. Leave all other webhooks untouched.
- Handle GitHub API pagination (webhooks list can be paginated for repos with many hooks, though unlikely).

## Failure Modes

- **Token lacks permissions**: Webhook creation fails with 404. Detection: check HTTP status code. Log actionable error about required scopes.
- **Deploy domain not resolvable**: Webhook creation succeeds but GitHub can't deliver. Detection: GitHub marks webhook as failing after first attempt. Not herald's problem to detect — GitHub shows this in repo settings.
- **Rate limiting**: GitHub returns 403 with rate limit headers. Detection: check `X-RateLimit-Remaining`. Log warning with reset time.
- **Stale webhook left on repo**: If herald's config is cleared and sync runs, it won't know about webhooks on repos it no longer references. Mitigation: this is acceptable — manual cleanup via GitHub UI or `gh` CLI.
