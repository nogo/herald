# Add secrets and env injection to stacks

## Outcome
Stacks with `secrets:` and `env_file:` configured have their env file and docker secret files written by herald before the update script runs, identical to how apps handle secrets. Update scripts receive a `COMPOSE_OVERRIDE_FILE` env var pointing to an override that includes the env file (absolute path) and docker secret file definitions. No manual file creation is required on the server.

## Values
1. Parity with apps — same secret mechanism, same config shape.
2. No writes into the IaC repo working tree — herald writes only to the stack deploy dir.
3. Backward compatibility — stacks without `secrets:` or `env_file:` behave exactly as before.

## Context
- `internal/config/config.go` — `Stack` struct (line 42–47) and `SecretRef` struct (line 49–53). Add `Secrets []SecretRef` and `EnvFile string` to `Stack`. The `validate()` function (line 117) must validate secret types for stacks, same as it does for apps (line 149–153).
- `internal/stacks/manager.go` — `Setup()` (line 68) and `Update()` (line 112) are the two entry points. `RunUpdateScript()` (line 180) builds the env slice passed to the script (line 199–204) — add `COMPOSE_OVERRIDE_FILE` here. `generateOverride()` (line 278) currently only adds Caddy labels and network — extend it to include env_file and secret definitions when present. `ComposeUp()` (line 148) already passes the override file to docker compose; no compose change needed there.
- `internal/secrets/store.go` — `Resolve()` (line 236) already handles `type: env` and `type: docker-secret` and returns `envVars` and `dockerSecrets` maps. No changes needed here.
- `internal/deployer/deployer.go` — reference for the full app secrets pattern: `Resolve()` call (line 102), `WriteEnvFile()` (line 122), `WriteSecret()` loop (line 136–142), override with secret file defs (line 220–226). Replicate this pattern in the stack manager.
- `internal/compose/compose.go` — `WriteEnvFile()` (line 138), `WriteSecret()` (line 153), `SecretFileDef` (line 35), `Override` struct (line 15). Already supports everything needed.

## Requirements

### 1. Config struct
Add to `Stack`:
```go
EnvFile string      `yaml:"env_file,omitempty" json:"env_file,omitzero"`
Secrets []SecretRef `yaml:"secrets,omitempty"  json:"secrets,omitzero"`
```

### 2. Validation
In `validate()`, for each stack with `len(stack.Secrets) > 0`, validate each `SecretRef.Type` is `"env"` or `"docker-secret"`, same error format as apps: `stack %q: secrets[%d]: type must be "env" or "docker-secret", got %q`.

### 3. Env file and docker secret file writes
In both `Setup()` and `Update()` (before `RunUpdateScript` / before `generateOverride`):

a. Call `m.Secrets.Resolve(stack.Secrets)` to get `envVars` and `dockerSecrets`.

b. If `stack.EnvFile != ""`: write `envVars` to `filepath.Join(deployDir, stack.EnvFile)` using `compose.WriteEnvFile`. Use `os.OpenFile` directly (not `os.Root`) since the target is inside `deployDir`. Mode `0600`.

c. If `len(dockerSecrets) > 0`: create `filepath.Join(deployDir, "secrets")` (mode `0700`), write each secret using `compose.WriteSecret`. Use `os.Root` on `deployDir` for scoped writes into `secrets/` sub-dir, same as deployer.go.

d. Log resolved key names at Info level (env keys + docker secret keys), same as deployer.go line 107–112. Never log values.

### 4. Compose override — env_file and secrets
Extend `generateOverride()` to accept `envFile string` and `dockerSecrets map[string]string` parameters.

If `envFile != ""`: set `svc.EnvFile = []string{filepath.Join(deployDir, envFile)}` (absolute path). This avoids relying on the relative path in the base compose.yml.

If `len(dockerSecrets) > 0`: populate `svc.Secrets` (service-level list) and `override.Secrets` (top-level `file:` definitions pointing to `filepath.Join(deployDir, "secrets", name)`), same pattern as deployer.go lines 210–226.

### 5. COMPOSE_OVERRIDE_FILE env var
In `RunUpdateScript()`, add to the env slice:
```go
"COMPOSE_OVERRIDE_FILE=" + filepath.Join(deployDir, "compose.override.yml"),
```
This allows update scripts to include the override: `docker compose -f "$COMPOSE_FILE" -f "$COMPOSE_OVERRIDE_FILE" ...`

### 6. ComposeUp
`ComposeUp()` already uses the override file (line 167). No change needed, but ensure `generateOverride` is called with the new parameters when setting up.

## Constraints
- `go build ./...` must pass.
- Do not modify files outside the Modifies list.
- Stacks with no `secrets:` and no `env_file:` must behave identically to before — no regressions.
- Never log secret values, only key names.
- Do not write any files into the IaC repo working tree (`<dataDir>/repo/`). All writes go to `deployDir` (`<stacksDir>/stacks/<stackName>/`).

## Failure Modes
- **Resolve fails (missing secret)**: deploy fails with clear error before any file writes. Blast radius: deploy blocked. Detection: error message names the missing key.
- **envFile absolute path conflicts with relative path in base compose.yml**: if the user's compose.yml has `env_file: .env.app` (relative) AND the override adds an absolute path, Docker Compose merges both and fails if the relative path doesn't exist. Detection: compose up error about missing env file. Mitigation: document that stacks using herald env injection should change their compose.yml `env_file` entry to `env_file: [{path: .env.app, required: false}]` or remove it and rely solely on the override.
- **Secrets written but compose override not updated**: containers don't receive secrets. Detection: `docker inspect <container>` shows no mounted secrets.

## Verification
```bash
go build ./...
go test ./internal/config/...
go test ./internal/stacks/...
```
Manual: configure a stack with `env_file: .env` and one `type: env` secret ref. Run `herald update <stack>`. Verify `<deployDir>/.env` exists with the correct key=value. Verify `COMPOSE_OVERRIDE_FILE` is set in the update script environment by adding `echo $COMPOSE_OVERRIDE_FILE` to the script temporarily.
