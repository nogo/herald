# Pre-flight secret validation at deploy and sync

## Outcome
Before any deploy or stack update begins, herald checks all referenced secrets and reports every missing required secret (no `generate`, not in store) in a single error. Operators see the complete list of what needs to be set before any work starts — no mid-deploy failures from a missing secret discovered halfway through. `herald sync` reports missing required secrets as warnings (non-blocking) so operators know what to set after a fresh `herald init`.

## Values
1. Fail early and completely — surface all missing secrets at once, not one at a time.
2. Warnings at sync, errors at deploy — `herald sync` should succeed so operators can set up incrementally; deploy must not proceed with missing required secrets.
3. Generatable secrets are not errors — `generate:` secrets that are absent are fine; they will be created at deploy time (wu-18).

## Context
- `internal/secrets/store.go` — add `MissingRequired(refs []SecretRef) ([]string, error)` that returns the keys of all refs that are absent from the store AND have no `generate` value. Calls `readSecrets()` once and checks all refs in one pass.
- `internal/deployer/deployer.go` — `Deploy()` (line 75). Add the validation call before step 1 (git sync). Return a single error listing all missing keys if any are found.
- `internal/stacks/manager.go` — `Update()` (line 112) and `Setup()` (line 68). Add the same validation call before any file operations.
- `cmd/sync.go` — read the current file to understand what `sync` does and where to add the warning output.
- `internal/config/config.go` — `SecretRef` struct has `Generate string` after wu-18. `MissingRequired` uses this field to skip generatable secrets.

## Requirements

### 1. Store.MissingRequired
```go
func (s *Store) MissingRequired(refs []SecretRef) ([]string, error)
```
- Calls `s.readSecrets()` once.
- For each ref: if `ref.Generate != ""`, skip (will be auto-generated). If key is absent from the store, add `ref.Key` to the missing list.
- Returns the sorted missing key list and any read error.
- Returns `nil, nil` if nothing is missing.

### 2. Deploy pre-flight (apps)
In `Deployer.Deploy()`, before step 1 (git sync), call:
```go
missing, err := d.Secrets.MissingRequired(app.Secrets)
```
If `err != nil`: return it.
If `len(missing) > 0`: return a single error:
```
app %q: missing required secrets (use `herald secret set <key>`): key1, key2, key3
```
List keys sorted alphabetically.

### 3. Stack pre-flight
In `StackManager.Update()` and `StackManager.Setup()`, same pattern:
```go
missing, err := m.Secrets.MissingRequired(stack.Secrets)
```
Error format:
```
stack %q: missing required secrets (use `herald secret set <key>`): key1, key2
```

### 4. Sync warnings
Read `cmd/sync.go` to understand the current sync flow. After the sync completes successfully (config reloaded, webhooks synced), iterate over all apps and stacks in the new config and call `MissingRequired` for each. Collect all missing keys across all entries. If any are found, print a warning block to stderr:
```
Warning: the following secrets are required but not set:
  app "myapp":    dev/smtp_password, dev/github_token
  stack "basalt-app-dev": dev/smtp_password
Run `herald secret set <key>` to set them before deploying.
```
Sync itself still exits 0 — this is advisory, not blocking.

### 5. No duplicate store reads
`MissingRequired` calls `readSecrets()` once per call. For sync, one call per app/stack is acceptable (sync is infrequent). For deploy, the pre-flight call and the later `Resolve()` call each read the store once — this is acceptable and correct (do not try to combine them).

## Constraints
- `go build ./...` must pass.
- Do not modify files outside the Modifies list.
- Do not block `herald sync` — warnings only, exit 0.
- Do block `herald deploy` and `herald update` — return error before any side effects (no git pull, no file writes).
- Generatable secrets (`Generate != ""`) must never appear in the missing list.

## Failure Modes
- **Missing list shows only first secret**: if validation returns on first missing key, the operator has to run deploy N times to discover N secrets. Detection: configure two missing secrets, run deploy, verify error lists both.
- **Generatable secret incorrectly listed as missing**: operator confusion — they don't need to set it. Detection: configure a `generate: base64` secret, remove it from store, run validation, verify it does not appear in the missing list.
- **Sync exits non-zero due to missing secrets**: breaks CI pipelines that run `herald sync`. Detection: run `herald sync` with missing secrets, check exit code.
