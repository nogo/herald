# Rename stacks to services throughout

## Outcome
The `stacks:` config key becomes `services:`. The Go type `Stack` becomes `Service`. All error messages, log output, and CLI help text say "service" instead of "stack". The mental model is explicit: **apps** = code you develop, **services** = software you operate (Nextcloud, Ghost, Vaultwarden).

## Values
1. Complete rename — no "stack" terminology left in user-facing output, config keys, or type names.
2. No filesystem or container disruption — deploy paths (`stacks_dir/stacks/<name>`) and Docker project names (`herald-stack-<name>`) are NOT renamed. Changing these would orphan existing container data and mounts. Internal paths are an implementation detail; the config language is the user-facing contract.
3. `stacks_dir` server field stays — it is the base deploy directory for all deployments, not specific to services. Renaming it is a separate concern.

## Requirements

### 1. Config type rename
In `internal/config/config.go`:
- Rename `Stack` struct → `Service`
- Rename `Stacks map[string]Stack` → `Services map[string]Service` with yaml tag `"services,omitempty"` and json tag `"services,omitempty"`
- In `validate()`: all error format strings change `"stack %q:"` → `"service %q:"` and `"stack:"` prefix in domain collision map → `"service:"`
- Do NOT rename `StacksDir` on `Server`

### 2. Package rename
- Create `internal/services/` directory
- Move `internal/stacks/manager.go` → `internal/services/manager.go`, change `package stacks` → `package services`
- Move `internal/stacks/manager_test.go` → `internal/services/manager_test.go`, change `package stacks` → `package services`
- Delete `internal/stacks/` directory
- Update the import path in all files that import `github.com/nogo/herald/internal/stacks` → `github.com/nogo/herald/internal/services`

### 3. Type renames in manager
In `internal/services/manager.go`:
- `StackManager` → `ServiceManager`
- `StackInfo` → `ServiceInfo`
- All log/error strings: "stack" → "service", "Stack" → "Service"
- The `stackDeployDir()` method and the path it returns (`stacks_dir/stacks/<name>`) are NOT renamed — filesystem paths must not change
- Docker project name `"herald-stack-"+stackName` is NOT renamed — would orphan running containers

### 4. All call sites
Update every file in the Modifies list:
- Import `internal/services` instead of `internal/stacks`
- `stacks.StackManager` → `services.ServiceManager`
- `stacks.StackInfo` → `services.ServiceInfo`
- String literals in CLI help, log messages, error messages: "stack" → "service"
- Config field access: `cfg.Stacks` → `cfg.Services`, `config.Stack` → `config.Service`

### 5. README
In `README.md`:
- Section heading "Stacks" → "Services"
- All explanatory text: "stack" → "service", "stacks" → "services"
- Config example blocks: `stacks:` → `services:`
- Command descriptions for `herald update`

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do NOT rename `StacksDir`, `stacks_dir`, filesystem paths, or Docker project names.
- After this WU, zero occurrences of `stacks:` as a yaml config key, `Stack` as a Go type name, or "stack" in user-facing strings (CLI, logs, errors). Internal variable names (e.g. loop vars `stack`, `stackName`) may be updated but are lower priority.
- The `internal/stacks/` directory must not exist after this WU.

## Failure Modes
- **Import path not updated in one file**: compile error. Detection: `go build ./...` fails.
- **Filesystem path renamed accidentally**: existing service deploy dirs become unreachable. Detection: `herald update <service>` fails to find deploy dir.
- **Docker project name renamed accidentally**: existing containers are orphaned; `docker compose up` creates a new project instead of updating. Detection: `docker ps` shows both old and new containers running.
- **`stacks_dir` renamed in config**: existing configs break on load. Detection: config load error at startup.
