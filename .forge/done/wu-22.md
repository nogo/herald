# Rename service deploy paths and Docker project names

## Outcome
The filesystem path segment `stacks/<name>` under `stacks_dir` becomes `services/<name>`. The Docker Compose project name `herald-stack-<name>` becomes `herald-svc-<name>`. The rename is complete: config key, Go types, error messages (wu-21), filesystem layout, and container naming all consistently use "service".

## Values
1. Complete consistency — no "stack" anywhere: not in config, not on disk, not in `docker ps` output.
2. Clean break — this WU assumes no running service containers and no existing service deploy directories. Do not add migration logic.

## Context
- `internal/services/manager.go` (created by wu-21) — `serviceDeployDir()` method returns `filepath.Join(m.Config.Server.StacksDir, "stacks", serviceName)`. Change `"stacks"` → `"services"`. Docker project name is built as `"herald-stack-"+serviceName` in `ComposeUp()` and `RunUpdateScript()` env. Change to `"herald-svc-"+serviceName`.
- `internal/config/config.go` — `Server.StacksDir` field. The yaml tag is `stacks_dir`. Rename field to `ServicesDir`, yaml tag to `services_dir`, json tag to `services_dir`. Update all references to `StacksDir` → `ServicesDir` throughout the codebase.
- All files referencing `Config.Server.StacksDir` — deployer also uses `StacksDir` for app deploy paths (`apps/<name>`). After rename to `ServicesDir` it still serves as the base deploy dir for both apps and services. The field name is a better fit regardless.

## Requirements

### 1. Service deploy directory path
In `internal/services/manager.go`, change `serviceDeployDir()`:
```go
// Before
return filepath.Join(m.Config.Server.ServicesDir, "stacks", serviceName)
// After
return filepath.Join(m.Config.Server.ServicesDir, "services", serviceName)
```

### 2. Docker project name
In `internal/services/manager.go`, change all occurrences of `"herald-stack-"+serviceName` → `"herald-svc-"+serviceName`. This affects `ComposeUp()` log and the `--project-name` flag, and the `STACK_NAME` env var passed to update scripts (change key to `SERVICE_NAME` and value remains the service name).

### 3. Config field rename
In `internal/config/config.go`:
- `Server.StacksDir string` → `Server.ServicesDir string`
- yaml tag: `"stacks_dir"` → `"services_dir"`
- json tag: `"stacks_dir"` → `"services_dir"`
- Default/validation logic referencing `StacksDir` → `ServicesDir`
- Error message: `"server.stacks_dir is required"` → `"server.services_dir is required"`

### 4. All call sites
Search for `StacksDir` across all Go files and replace with `ServicesDir`. Read each affected file before editing. The deployer uses `Config.Server.StacksDir` to build app deploy paths (`filepath.Join(...StacksDir, "apps", appName)`); the rename to `ServicesDir` does not change the path logic, only the field name.

### 5. README
In `README.md`:
- Config example: `stacks_dir: /opt/deploy` → `services_dir: /opt/deploy`
- Any mention of `/opt/deploy/stacks/` path layout → `/opt/deploy/services/`
- Description of the field

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Do not change the actual base directory value (`/opt/deploy`) — only the subdirectory segment and field name change.
- Do not add migration code for existing `stacks/` directories. This is a clean break.
- After this WU: zero occurrences of `StacksDir` or `stacks_dir` in Go source or README. Zero occurrences of `"herald-stack-"` as a project name prefix. Zero occurrences of `"/stacks/"` as a deploy path segment in `serviceDeployDir`.

## Failure Modes
- **`StacksDir` reference missed**: compile error. Detection: `go build ./...` fails.
- **App deploy path broken**: deployer uses `ServicesDir` to build `apps/<name>` path — must still work. Detection: `herald deploy <app>` fails to find or create app dir.
- **Old project name in a running container**: out of scope (constraint: no running containers assumed).

## Verification
```bash
go build ./...
go test ./...
grep -rn 'StacksDir\|stacks_dir\|herald-stack-\|"stacks",' internal/ cmd/ --include="*.go"
# All of the above should return nothing.
```
Manual: `herald update <service>` creates deploy dir at `<services_dir>/services/<name>`, not `<services_dir>/stacks/<name>`. `docker ps` shows project name `herald-svc-<name>`.
