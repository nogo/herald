# Unify CLI commands for stacks

## Outcome

`herald deploy <stack>` works for all stacks (both `repo:` and `path:` types). `herald deploy --all` deploys all stacks. `herald down <stack>` works for all stacks. The `herald update` command is deleted. The `herald logs` and `herald exec` commands are deleted. The CLI command groups are simplified: no separate "Apps" and "Services" groups.

## Values

1. Minimal command surface — every command does something only herald can do.
2. Clean break — no deprecated aliases, no transition period.
3. Consistent terminology — "stack" everywhere in help text and error messages.

## Context

- `cmd/deploy.go` — current deploy command, references `Cfg.Apps`. Must reference `Cfg.Stacks`.
- `cmd/down.go` — current down command, references `Cfg.Apps`. Must reference `Cfg.Stacks`.
- `cmd/update.go` — entire file deleted.
- `cmd/logs.go` — entire file deleted.
- `cmd/exec.go` — entire file deleted.
- `cmd/root.go` — command group definitions (line 114-121). Remove "apps" and "services" groups, replace with "stacks" group.
- `docs/architecture.md` — "Command Surface" section.

## Creates

None.

## Modifies

cmd/deploy.go
cmd/down.go
cmd/root.go

## Requirements

### 1. deploy.go

- `Use` becomes `"deploy [stack]"`.
- `Short` becomes `"Deploy a stack"`.
- References `Cfg.Stacks` instead of `Cfg.Apps`.
- `--all` iterates `Cfg.Stacks` (sorted by name).
- When no args: lists available stacks.
- When stack not found: error lists available stacks.
- `GroupID` changes from `"apps"` to `"stacks"`.

### 2. down.go

- `Use` becomes `"down <stack>"`.
- `Short` becomes `"Stop and remove a stack's containers"`.
- References `Cfg.Stacks` instead of `Cfg.Apps`.
- `GroupID` changes from `"apps"` to `"stacks"`.

### 3. root.go

Replace command groups. Remove `"apps"` and `"services"` groups. Add `"stacks"` group. Keep `"daemon"`, `"previews"`, `"secrets"`, `"infra"`, `"auth"`, `"ops"` as needed (remove `"ops"` if no commands remain in it after deleting logs/exec).

### 4. Delete update.go, logs.go, exec.go

Remove these files entirely. They are not modified — they are deleted.

### 5. Tests

No new test files needed. The CLI commands are thin wrappers around the deployer. Verify by building and checking help output.

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list (except deleting update.go, logs.go, exec.go).
- `herald deploy` must create the deployer with `Cfg.Stacks` context, not hardcode stack type checks.

## Failure Modes

- **Orphaned command registration**: Deleted files still referenced in `init()`. Detection: `go build` fails if a deleted file's `init()` registered a command that's still expected.
- **Missing group ID**: Command with deleted group ID causes panic. Detection: `go build` + `herald --help` in verification.

## Verification

```bash
go build ./...
./bin/herald --help 2>&1 | grep -v "apps\|services"
go vet ./cmd/...
```
