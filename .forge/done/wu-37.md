# Delegate preview deploy to unified deployer

## Outcome

`PreviewManager.Deploy()` delegates the core deploy pipeline (secrets, env, override, compose up) to shared helpers from the deployer package instead of reimplementing them. Preview retains its own lifecycle management (state file, teardown, cleanup, branch slug generation) but the deploy steps are not duplicated. The `DeepMerge` bug in preview's override generation is fixed by using `DeepMergeYAML`.

## Values

1. No pipeline duplication — preview uses the same helpers as the deployer.
2. Preview lifecycle preserved — state tracking, teardown, cleanup are preview-specific and stay in the preview package.
3. Bug fix — `DeepMergeYAML` replaces `DeepMerge`, fixing YAML tag loss (`!override`).

## Context

- `internal/preview/manager.go` — `Deploy()` (lines 81-211), `generateOverride()` (lines 379-457), `runCompose()` (lines 363-369), `gitSync()` (lines 344-347). The deploy pipeline is the third copy.
- `internal/deployer/helpers.go` — `BuildEnvMap`, `GenerateOverride`, `WriteEnvFile`, `WriteDockerSecrets` from wu-30.
- `internal/compose/override.go` or `compose/merge.go` — `DeepMergeYAML` function.
- `internal/preview/manager_test.go` — existing tests.
- `docs/architecture.md` — "Deploy Pipeline": preview uses deployer, does not duplicate it.

## Requirements

### 1. Deploy() refactoring

Replace the inline deploy steps in `Deploy()` with calls to deployer helpers:

- Secrets resolution: keep direct call to `m.Secrets.Resolve()` (same as now).
- Env file: use `deployer.WriteEnvFile` or `compose.WriteEnvFile` (whichever was established in wu-30).
- Docker secrets: use `deployer.WriteDockerSecrets`.
- Override: use `deployer.GenerateOverride(OverrideParams{...})` instead of the local `generateOverride` method. Pass `DefaultPort: "3000"` (previews are always repo stacks), `InternalNet: "herald-preview-" + id + "-internal"`, and the preview-specific labels (`com.herald.preview`).
- Compose up and compose down: keep preview's own `runCompose`/`runComposeDown` (they use `runner.RunCmd` not `runner.RunCmdStream`, and don't need UI streaming).

### 2. Delete local generateOverride

Remove the `generateOverride` method from `PreviewManager`. All override generation goes through the shared helper.

### 3. Preview-specific labels

The preview override needs an additional label `"com.herald.preview": previewID`. The `GenerateOverride` helper must support extra labels, or the preview can add them after calling the helper. Preferred: `OverrideParams` has an `ExtraLabels map[string]string` field.

### 4. Fix DeepMerge → DeepMergeYAML

The shared `GenerateOverride` already uses `DeepMergeYAML` (from wu-30). By switching to the shared helper, the preview bug is fixed automatically.

### 5. Config.Apps → Config.Stacks

`Deploy()` references `m.Config.Apps[appName]`. Change to `m.Config.Stacks[appName]`.
`Cleanup()` and `branchExists()` also reference `Config.Apps`. Change to `Config.Stacks`.

### 6. Tests

- Update test fixtures to use `Config.Stacks`.
- Test that preview override contains `com.herald.preview` label.
- Test that inline override merge preserves YAML tags (regression test for the DeepMerge bug).

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- Preview state file format (`previews.json`) is unchanged.
- `compose/context.go` `ResolvePreview` is unchanged (it reads from state file, not config).
- `Teardown`, `Remove`, `Cleanup`, `List` methods are unchanged.

## Failure Modes

- **Missing preview label**: `docker image prune` in `Remove()` filters by `com.herald.preview` label. If override doesn't include it, cleanup leaves orphaned images. Detection: test that override contains the label.
- **Import cycle**: `preview` imports `deployer` for helpers. Verify `deployer` doesn't import `preview`. Detection: `go build`.
- **Wrong default port**: Preview uses `"3000"` (it's always a repo stack). If the helper defaults differently, containers don't route. Detection: test override contains correct port.
