# Update README and config reference docs

## Outcome

`README.md` and `docs/config.md` reflect the unified stack model. Users see `stacks:` in all config examples. Command reference shows `herald deploy <stack>`, not `herald deploy <app>`. The `herald update`, `herald logs`, and `herald exec` commands are removed from documentation. The architecture section matches `docs/architecture.md`. The comparison table and feature descriptions are accurate.

## Values

1. Accuracy — docs match the actual CLI and config format. No references to `apps:` or `services:` config keys.
2. Clarity — the "stack" concept is explained once, early, with a simple example.
3. Brevity — don't over-explain the migration. New docs describe the current state as if it always existed.

## Context

- `README.md` — current state references `apps:` and `services:` sections, "Apps" and "Services" command groups, `herald update`, `herald logs`, `herald exec`.
- `docs/config.md` — full config reference with separate `apps` and `services` sections, filesystem layout with `apps/` and `services/` subdirectories.
- `docs/architecture.md` — already describes target architecture. Verify file layout section matches.
- `docs/project.md` — already updated. No changes needed.

## Requirements

### 1. README.md

- Config example: replace `apps:` + `services:` with single `stacks:` section showing both a repo stack and a path stack.
- Remove "Apps = your code" / "Services = software you operate" distinction. Replace with: "Each stack has a domain, secrets, and a source — either a GitHub repo or a directory in the IaC repo."
- Commands section: one "Stacks" group with `herald deploy <stack>`, `herald deploy --all`, `herald down <stack>`. Remove "Apps" and "Services" command groups. Remove `herald update`, `herald logs`, `herald exec`.
- Architecture section: flat deploy dir (`/opt/deploy/<name>/`), no `apps/` or `services/` subdirs.
- Comparison table: review for accuracy (no functional changes, just terminology).
- Security section: no changes needed unless it references "apps" or "services" specifically.

### 2. docs/config.md

- Top-level structure: `server:` + `stacks:` (remove `apps:` and `services:` as separate sections).
- One `stacks` section with a unified field table. Fields that only apply to `repo:` stacks (branch, tag, tag_pattern, compose, override, preview) are noted as such. Fields that only apply to `path:` stacks (auto_deploy, update) are noted as such.
- Update `update_script` → `update` in YAML key name.
- Filesystem layout: flat `<services_dir>/<name>/` structure. Remove `apps/<name>/` and `services/<name>/` paths.
- Docker project names: `herald-<name>` for all stacks. Remove `herald-svc-<name>`.
- Network names: `herald-<name>-internal` for all stacks. Remove `herald-svc-<name>-internal`.
- Secrets section: reference "stacks" not "apps and services."
- Preview section: references `stacks:` config, not `apps:`.
- Multiple environments example: uses `stacks:` key.
- Networking section: unified naming.

### 3. docs/architecture.md

- Verify file layout section matches the new flat structure.
- Verify command surface table is accurate.
- Minor wording fixes if any section still says "app" or "service" where "stack" is meant.
