# Scaffold herald Go project

## Outcome

Running `go build ./...` from the project root produces a `herald` binary. Running `herald version` prints the version string. Running `herald` with no arguments prints usage help showing subcommands: `init`, `serve`, `status`, `deploy`, `update`, `secret`, `preview`, `sync`. No subcommand is implemented yet beyond `version` — all others print "not implemented" and exit 0.

## Values

1. Clean project structure — idiomatic Go module layout that supports growth to 12+ subcommands and multiple internal packages.
2. Minimal dependencies — only add what's needed now (cobra for CLI, nothing else).
3. Build correctness — `go build`, `go vet`, `go test` all pass with zero errors.

## Context

- This is a greenfield Go project. There is no existing Go code. **Target Go version: 1.26.**
- The project will eventually be a deployment daemon that manages Docker Compose stacks, Caddy reverse proxy, GitHub webhooks, and age-encrypted secrets.
- The binary name is `herald`. The Go module path should be `github.com/nogo/herald`.
- The CLI framework is Cobra (`github.com/spf13/cobra`).
- Future WUs will add internal packages: `config`, `secrets`, `webhook`, `docker`, `caddy`, `github`, `preview`.
- **Go 1.26 idioms to follow throughout the project:**
  - Use `log/slog` for all structured logging (not `log` package).
  - Use `errors.AsType[T](err)` for typed error assertions (not `errors.As(err, &target)`).
  - Use `new(value)` for pointer field initialization (not helper functions or `&v` patterns).
  - Use `sync.WaitGroup.Go(func() {...})` for goroutine spawning (not manual `Add(1)`/`Done()`).
  - Use `testing.T.Context()` and `testing.T.Chdir()` in tests.
  - Use `strings.Lines()`, `strings.SplitSeq()`, `strings.FieldsSeq()` for string iteration where applicable.
  - Use `crypto/rand.Text` for generating random strings (webhook secrets, etc.).
  - Use `slog.DiscardHandler` in tests to silence log output.
  - Use `omitzero` JSON struct tags for optional zero-value fields (not `omitempty` — which doesn't work correctly for `time.Time`, structs, etc.).
  - Use `http.CrossOriginProtection` for CSRF protection on non-webhook endpoints.
  - Use `os.OpenRoot` for directory-scoped filesystem access where security matters.
  - Container-aware `GOMAXPROCS` is automatic in Go 1.25+ — do NOT add `uber-go/automaxprocs`.
  - Use `go fix ./...` in the Makefile to auto-modernize code.

## Creates

- `go.mod` — Go module definition.
- `go.sum` — dependency checksums (generated by `go mod tidy`).
- `main.go` — entry point, calls `cmd.Execute()`.
- `cmd/root.go` — root Cobra command with usage text, persistent flags for `--config` (path to config file, default `/etc/herald/config.yml`) and `--verbose`.
- `cmd/version.go` — `herald version` subcommand, prints version from build-time ldflags.
- `cmd/init.go` — `herald init <repo>` stub, prints "not implemented".
- `cmd/serve.go` — `herald serve` stub.
- `cmd/status.go` — `herald status` stub.
- `cmd/deploy.go` — `herald deploy <app>` stub.
- `cmd/update.go` — `herald update <stack>` stub.
- `cmd/secret.go` — `herald secret <set|get|list|import>` stub with subcommands.
- `cmd/preview.go` — `herald preview <list>` stub.
- `cmd/sync.go` — `herald sync` stub.

## Modifies

None.

## Requirements

### 1. Go module

Initialize a Go module at `github.com/nogo/herald` with `go 1.26` directive. Add `github.com/spf13/cobra` as the only dependency. Run `go mod tidy` to generate `go.sum`. Use the `tool` directive in `go.mod` if any build tools are needed (not the legacy `tools.go` pattern).

### 2. CLI structure

Use Cobra for all commands. The root command prints help text describing herald:

```
herald — deploy daemon for self-hosted infrastructure

Usage:
  herald [command]

Available Commands:
  init        Bootstrap server from IaC repository
  serve       Start webhook listener and deploy daemon
  status      Show all services, domains, and health
  deploy      Force re-deploy an app
  update      Run update script for a managed stack
  secret      Manage encrypted secrets
  preview     Manage preview deployments
  sync        Reconcile config with running state
  version     Print herald version

Flags:
  -c, --config string   Path to config file (default "/etc/herald/config.yml")
  -v, --verbose          Enable verbose output
  -h, --help             help for herald
```

### 3. Version command

`herald version` prints: `herald version <version> (<commit> <date>)`. The values `version`, `commit`, and `date` are injected via `-ldflags` at build time. Default to `dev`, `unknown`, `unknown` when not set.

### 4. Stub commands

Every command listed in the help text must exist as a Cobra command. Running any stub command prints `"herald <command>: not implemented"` to stderr and exits with code 0. The `secret` command has subcommands: `set`, `get`, `list`, `import` — all stubs.

### 5. Project layout

```
herald/
  main.go
  cmd/
    root.go
    version.go
    init.go
    serve.go
    status.go
    deploy.go
    update.go
    secret.go
    preview.go
    sync.go
  go.mod
  go.sum
```

No `internal/` packages yet — those will be added by future WUs.

### 6. Build

`go build -o herald .` must produce a working binary. Add a simple `Makefile` with targets: `build`, `test`, `clean`, `fix`. The `build` target should inject version info via ldflags. The `fix` target runs `go fix ./...` to auto-modernize code.

## Constraints

- `go build ./...` must pass.
- `go vet ./...` must pass.
- `go test ./...` must pass (no tests yet, but the command must succeed).
- Do not add any internal packages or business logic beyond the CLI skeleton.
- Do not add any configuration parsing, Docker integration, or network listeners.

## Failure Modes

- **Wrong module path**: If the module path doesn't match `github.com/nogo/herald`, imports in future WUs will break. Detection: check `go.mod` module line.
- **Missing stub command**: If a command is missing, future WUs that add implementation will fail to find the command file. Detection: run `herald --help` and verify all commands appear.
- **Cobra version mismatch**: Using an incompatible Cobra version could cause API differences. Detection: `go build` fails.

## Verification

```bash
go build ./...
go vet ./...
go test ./...
./herald version
./herald --help
./herald init test-repo 2>&1 | grep "not implemented"
./herald secret set foo bar 2>&1 | grep "not implemented"
```
