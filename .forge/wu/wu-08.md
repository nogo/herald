# Add init command

## Outcome

Running `herald init nogo/srv2` on a fresh server bootstraps the entire deployment infrastructure: clones the server IaC repository, generates the age encryption key, starts Caddy, registers GitHub webhooks on all configured repos, and clones all app repositories. After init completes, running `herald serve` starts receiving webhooks and deploying apps. The server goes from bare to fully configured with one command.

## Values

1. Idempotency — running `herald init` twice must not break anything. It should detect what's already done and skip it.
2. Fail-fast with clear errors — if a prerequisite is missing (Docker not installed, port in use), fail immediately with an actionable error.
3. Progressive output — each step prints its status so the user can follow along.

## Context

- `cmd/init.go` — stub command. This WU replaces it with the full bootstrap flow.
- `internal/config/config.go` — config types and loader. `Config` is loaded from `config.yml` in the cloned server repo.
- `internal/secrets/store.go` — `Store.Init()` generates the age key if missing.
- `internal/caddy/caddy.go` — `CaddyManager.Start()` starts caddy-docker-proxy.
- `internal/deployer/deployer.go` — `Deployer.Deploy()` clones and deploys an app.
- `internal/github/webhooks.go` — `SyncWebhooks()` registers webhooks on GitHub.
- The init command takes one argument: the GitHub repo path for this server's IaC repo (e.g., `nogo/srv2`). It clones this repo to `<data_dir>/repo/` (e.g., `/etc/herald/repo/`).
- The config file is expected at `<cloned-repo>/config.yml`.
- After init, `herald serve` and other commands use `--config <data_dir>/repo/config.yml` automatically.

## Creates

- `internal/init/bootstrap.go` — bootstrap orchestration logic.

## Modifies

- `cmd/init.go` — implement the full init flow.
- `cmd/root.go` — if `--config` is not explicitly set and `<data_dir>/repo/config.yml` exists, use it as the default config path.

## Requirements

### 1. Init command signature

```
herald init <github-repo> [flags]

Arguments:
  github-repo    GitHub repository path (e.g., nogo/srv2)

Flags:
  --github-token string   GitHub personal access token (can also be set via GITHUB_TOKEN env var)
  --data-dir string       Herald data directory (default /etc/herald)
  --stacks-dir string     Override stacks directory (default from config)
```

### 2. Prerequisite checks

Before doing anything, verify:

1. **Docker is installed and accessible**: Run `docker info` and check exit code. If it fails: `"Docker is not installed or not accessible. Install Docker and ensure the current user is in the 'docker' group."`.
2. **Docker Compose is available**: Run `docker compose version`. If it fails: `"Docker Compose plugin is not installed."`.
3. **Git is installed**: Run `git --version`. If it fails: `"git is not installed."`.
4. **Ports 80 and 443 are free**: Check with `ss -tlnp | grep ':80 \|:443 '` or attempt to bind. If occupied: `"Ports 80/443 are in use. Stop the existing proxy before running init."`.
5. **Data directory is writable**: Check write permissions on `--data-dir`.

Print each check with pass/fail:
```
Checking prerequisites...
  Docker:          ✓ Docker 27.5.1
  Docker Compose:  ✓ v2.32.4
  Git:             ✓ 2.43.0
  Ports 80/443:    ✓ available
  Data directory:  ✓ /etc/herald (writable)
```

### 3. Bootstrap steps

Execute these steps in order. Each step prints its status. If a step fails, stop and print the error — do not continue.

**Step 1: Clone server IaC repo**
```
Cloning server repository...
  → git clone https://github.com/nogo/srv2.git /etc/herald/repo
  ✓ Repository cloned
```
If the directory already exists and is a git repo, do `git pull` instead:
```
  → Repository already cloned, pulling latest...
  ✓ Repository updated
```
If a GitHub token is provided, use it in the clone URL for private repos.

**Step 2: Load and validate config**
```
Loading configuration...
  → /etc/herald/repo/config.yml
  ✓ Config loaded: 4 apps, 2 stacks
```

**Step 3: Initialize secrets store**
```
Initializing secrets store...
  → Generated age key: /etc/herald/age.key
  ✓ Secrets store initialized
  ⚠ IMPORTANT: Back up /etc/herald/age.key — it cannot be recovered if lost!
```
If the key already exists:
```
  → Age key already exists: /etc/herald/age.key
  ✓ Secrets store ready
```

**Step 4: Set webhook secret (if not already set)**
```
Configuring webhook secret...
  → Generated webhook secret
  ✓ Webhook secret stored in secrets store
```
If `herald/webhook_secret` already exists in the store, skip. Otherwise, generate a random secret using `crypto/rand.Text(32)` (Go 1.24+) and store it.

**Step 5: Store GitHub token**
```
Storing GitHub token...
  ✓ GitHub token stored in secrets store
```
Store the GitHub token in the secrets store at `herald/github_token` so it's encrypted at rest. The config file references `${GITHUB_TOKEN}` which is expanded from env — but for persistence across reboots, store it encrypted.

**Step 6: Create stacks directory**
```
Creating directories...
  → /opt/deploy/apps/
  → /opt/deploy/stacks/
  → /opt/deploy/envs/
  ✓ Directories created
```

**Step 7: Start Caddy**
```
Starting Caddy reverse proxy...
  → Creating 'caddy' Docker network
  → Starting caddy-docker-proxy
  ✓ Caddy running on :80/:443
```

**Step 8: Register GitHub webhooks**
```
Registering GitHub webhooks...
  → nogo/budget-app    + created
  → nogo/sidenote      + created
  → nogo/srv2          + created (self-update)
  ✓ 3 webhooks registered
```

**Step 9: Clone app repositories (but don't deploy yet)**
```
Cloning app repositories...
  → budget    nogo/budget-app:main → /opt/deploy/apps/budget/repo
  → tracker    nogo/budget-app:main → /opt/deploy/apps/tracker/repo
  → sidenote  nogo/sidenote:main   → /opt/deploy/apps/sidenote/repo
  ✓ 3 repositories cloned
```

```

Herald initialized successfully!

Server:     srv2
Config:     /etc/herald/repo/config.yml

     herald deploy --all

     herald install

```

### 5. Idempotency

Every step must check if its work is already done:
- Repo already cloned → pull instead
- Age key exists → skip generation
- Webhook secret exists → skip generation
- Caddy already running → skip start
- Webhooks already registered → skip creation
- App repos already cloned → pull instead

Running `herald init nogo/srv2` a second time should print mostly "already done" messages and complete quickly.

### 6. Default config path

In `cmd/root.go`, modify the config loading logic: if `--config` is not explicitly set by the user, check if `<data_dir>/repo/config.yml` exists. If it does, use it as the default. This way, after init, users don't need to pass `--config` to every command.

### 7. Deploy --all flag

Add a `--all` flag to `herald deploy`. When set, deploy all apps in the config sequentially. This is mentioned in the completion message and should work after init.

## Constraints

- `go build ./...` must pass.
- `go test ./...` must pass.
- The init command must work on a fresh Debian 12 server with Docker already installed.
- Do not install Docker — that's a prerequisite the user handles.
- Do not modify system-level configs (sysctl, firewall, etc.).
- The init command must be runnable by a non-root user who is in the `docker` group. Exception: creating `/etc/herald/` may require root. If the data dir doesn't exist and can't be created, suggest: `"Run: sudo mkdir -p /etc/herald && sudo chown $(whoami) /etc/herald"`.
- Never print secret values (webhook secret, GitHub token, age key contents).

## Failure Modes

- **Docker not installed**: Caught by prerequisite check. Clear error message.
- **GitHub token invalid**: Webhook registration fails with 401. Print: `"GitHub token is invalid or expired."`.
- **Port 80/443 occupied by nginx-proxy**: Caught by port check. User must stop existing proxy first.
- **Private repo without token**: Clone fails. Print: `"Cannot clone nogo/srv2. If this is a private repo, provide --github-token."`.
- **Disk full**: Various steps fail with IO errors. Not specifically handled — OS error messages are sufficient.
- **Init interrupted (Ctrl+C)**: Partial state is left. Re-running init picks up where it left off due to idempotency.
