# Add systemd service integration

## Outcome

Running `herald install` creates a systemd service unit that starts herald on boot and keeps it running. Running `herald uninstall` removes the service. After installation, `systemctl status herald` shows the service running, and `journalctl -u herald` shows herald's logs. The service automatically restarts on crash and starts after Docker.

## Values

1. Reliability — herald must survive crashes and reboots. Systemd handles restart and boot ordering.
2. Security — the service runs as a dedicated user (or the installing user), not as root. Only Docker socket access is needed.
3. Simplicity — one command to install, one to uninstall. No manual unit file editing.

## Context

- `cmd/root.go` — root command. `--data-dir` flag (default `/etc/herald/`). `--config` flag.
- `cmd/serve.go` — `herald serve` starts the webhook HTTP server. This is what the systemd service runs.
- Herald needs access to: Docker socket (`/var/run/docker.sock`), data directory (`/etc/herald/`), stacks directory (`/opt/deploy/`), git and docker compose binaries.
- The service should run `herald serve` with the appropriate flags.
- Herald logs to stdout/stderr — systemd captures this via the journal.

## Creates

- `internal/systemd/service.go` — systemd unit file generation and installation.
- `internal/systemd/service_test.go` — unit tests for generated unit file content.
- `cmd/install.go` — `herald install` command.
- `cmd/uninstall.go` — `herald uninstall` command.

## Modifies

- `cmd/root.go` — add `install` and `uninstall` to available commands.

## Requirements

### 1. Systemd unit file

Generate a unit file at `/etc/systemd/system/herald.service`:

```ini
[Unit]
Description=Herald - deployment daemon
Documentation=https://github.com/nogo/herald
After=network-online.target docker.service
Wants=network-online.target docker.service
Requires=docker.service

[Service]
Type=simple
User=<user>
Group=<group>
ExecStart=<herald-binary-path> serve --config <config-path> --data-dir <data-dir>
Restart=on-failure
RestartSec=10
TimeoutStartSec=30
TimeoutStopSec=30

# Environment
Environment=GITHUB_TOKEN=<token-if-set>
EnvironmentFile=-/etc/herald/environment

# Security hardening
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/etc/herald /opt/deploy /var/run/docker.sock
PrivateTmp=true

# Logging
StandardOutput=journal
StandardError=journal
SyslogIdentifier=herald

[Install]
WantedBy=multi-user.target
```

### 2. Install command

`herald install [flags]`:

Flags:
- `--user string` — user to run the service as (default: current user).
- `--start` — start the service immediately after installing (default: true).
- `--enable` — enable the service to start on boot (default: true).

Steps:
1. Detect the herald binary path (`os.Executable()`).
2. Detect the config path (from `--config` flag or default).
3. Detect the data directory (from `--data-dir` flag or default).
4. Generate the unit file with detected values.
5. Write to `/etc/systemd/system/herald.service`. This requires root — if not root, print: `"Installing systemd service requires root. Run: sudo herald install"` and exit 1.
6. Create `/etc/herald/environment` file (empty, for user to add env vars like `GITHUB_TOKEN`). Set permissions to `0600`.
7. Run `systemctl daemon-reload`.
8. If `--enable` (default): run `systemctl enable herald`.
9. If `--start` (default): run `systemctl start herald`.
10. Print:

```
Herald service installed:
  Unit:    /etc/systemd/system/herald.service
  User:    deploy
  Config:  /etc/herald/repo/config.yml
  Data:    /etc/herald/
  Env:     /etc/herald/environment
  Status:  running (enabled)

Commands:
  systemctl status herald     View service status
  journalctl -u herald -f     Follow logs
  systemctl restart herald    Restart service
  herald uninstall            Remove service
```

### 3. Uninstall command

`herald uninstall`:

1. Stop the service: `systemctl stop herald`.
2. Disable the service: `systemctl disable herald`.
3. Remove the unit file: `/etc/systemd/system/herald.service`.
4. Run `systemctl daemon-reload`.
5. Print: `"Herald service uninstalled. Data and config at /etc/herald/ were NOT removed."`.

Do NOT remove the data directory, config, secrets, or deployed apps. Only remove the systemd service.

Requires root — same check as install.

### 4. Environment file

Create `/etc/herald/environment` with:

```sh
# Herald environment variables
# Add environment variables here. They will be loaded by the systemd service.
# Example:
# GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

This file is loaded by systemd's `EnvironmentFile` directive. It allows the user to set `GITHUB_TOKEN` without embedding it in the unit file (which is world-readable).

Permissions: `0600`, owned by the service user.

### 5. Service user

If the specified user doesn't exist, DO NOT create it. Print: `"User '<user>' does not exist. Create it first: sudo useradd -r -s /bin/false -G docker herald"` and exit 1.

The user must be in the `docker` group. Check this and warn if not: `"Warning: user '<user>' is not in the 'docker' group. Herald needs Docker access."`.

### 6. Security hardening

The generated unit file includes systemd security directives:
- `NoNewPrivileges=true` — prevent privilege escalation.
- `ProtectSystem=strict` — mount filesystem read-only except `ReadWritePaths`.
- `ProtectHome=true` — hide /home, /root, /run/user.
- `ReadWritePaths` — only the directories herald needs to write to.
- `PrivateTmp=true` — private /tmp namespace.

These directives restrict what herald can do even if compromised. The `ReadWritePaths` must include all directories herald writes to:
- `/etc/herald` — data dir (secrets, state files).
- The configured `stacks_dir` (e.g., `/opt/deploy`) — app deployments.
- `/var/run/docker.sock` — Docker communication.

### 7. Serve command daemon behavior

Modify `herald serve` to handle systemd readiness:
- After the HTTP server is listening and Caddy is verified running, log: `"herald ready, listening on :<port>"`.
- Handle SIGTERM gracefully (already implemented in wu-04).
- Log rotation is handled by journald — herald should not manage its own log files.

### 8. Helper: systemd unit generation

```go
type ServiceConfig struct {
    BinaryPath  string
    ConfigPath  string
    DataDir     string
    User        string
    Group       string
    StacksDir   string
    Port        int
}

func GenerateUnitFile(cfg ServiceConfig) string
func Install(cfg ServiceConfig) error
func Uninstall() error
func IsInstalled() bool
```

Unit file generation should be a pure function (returns string) for easy testing.

## Constraints

- `go build ./...` must pass.
- `go test ./...` must pass.
- Install and uninstall require root. Check `os.Getuid() == 0` and fail with a clear message if not.
- Do not create system users — only verify they exist.
- Do not modify Docker configuration.
- Do not remove user data on uninstall — only the systemd unit file.
- The generated unit file must be valid systemd syntax. Test by checking `systemd-analyze verify` if available.
- Environment file must have `0600` permissions — it may contain secrets.

## Failure Modes

- **Not running as root**: Install/uninstall fail. Detection: check UID. Clear error message with `sudo` suggestion.
- **Docker not started**: Service starts but herald can't connect to Docker. Detection: `herald serve` logs Docker connection error. Mitigation: `After=docker.service` and `Requires=docker.service` in unit file.
- **Wrong user/group**: Service fails to start with permission error. Detection: `systemctl status herald` shows the error. Mitigation: validate user exists and is in docker group before installing.
- **Binary moved after install**: Service fails because ExecStart path is wrong. Detection: `systemctl status` shows "file not found". Mitigation: document that reinstalling after moving the binary is required.
- **Config file missing at boot**: Service starts but herald can't load config. Detection: herald logs the error and exits, systemd restarts it (with `RestartSec=10` backoff).

## Verification

```bash
go build ./...
go test ./internal/systemd/...

# Manual integration test (requires root):
# 1. sudo herald install --user $(whoami)
# 2. systemctl status herald  → active (running)
# 3. journalctl -u herald -n 20  → shows herald logs
# 4. sudo systemctl restart herald  → restarts cleanly
# 5. sudo herald uninstall
# 6. systemctl status herald  → not found
# 7. ls /etc/herald/  → data still exists
```
