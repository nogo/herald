# Add config file base layer to stacks

## Outcome
A stack can declare `config: path/to/config.dev.env` pointing to a file in the IaC repo. Herald reads it as a base layer of key=value pairs, overlays resolved `type: env` secrets on top, and writes the merged result to `env_file`. Non-secret config (URLs, hostnames, feature flags) lives version-controlled in the IaC repo; secrets live in the encrypted store. The two never need to be manually combined.

## Values
1. Git history and PR reviews for config changes — config file is committed.
2. Secrets always win — overlay semantics, same as GitHub Actions environments.
3. No silent data loss — key collisions are logged at Debug level so the operator knows an overlay occurred.

## Context
- `internal/config/config.go` — `Stack` struct. Add `ConfigFile string`. The path is relative to the IaC repo dir (resolved at runtime by the stack manager, not at config load time — the IaC repo may not be cloned yet when config loads).
- `internal/stacks/manager.go` — `repoDir()` (line 42) returns the IaC repo path (`<dataDir>/repo`). The config file is at `filepath.Join(m.repoDir(), stack.ConfigFile)`. The env merge happens in the same step as requirement 3b of wu-16: read config file → base map, overlay envVars from `Resolve()` → pass merged map to `compose.WriteEnvFile`.
- `internal/compose/compose.go` — `WriteEnvFile()` (line 138) takes `map[string]string`. The merge produces a single map; `WriteEnvFile` is called once with the merged map.
- wu-16 (already implemented before this WU runs) — establishes the `EnvFile` write path and the `Resolve()` call. This WU extends step 3b of wu-16 only; all other wu-16 behavior is unchanged.

## Requirements

### 1. Config struct
Add to `Stack`:
```go
ConfigFile string `yaml:"config,omitempty" json:"config,omitzero"`
```
No validation beyond ensuring it's a non-empty string if present. Existence is checked at runtime (stack setup/update), not at config load.

### 2. Config file loading
When `stack.ConfigFile != ""`, read the file at `filepath.Join(m.repoDir(), stack.ConfigFile)` and parse it as `KEY=VALUE` lines (one per line, `#` comments ignored, blank lines ignored, no shell quoting — values are literal strings from the `=` to end of line).

If the file does not exist: return an error — `config file %q not found in IaC repo`. This is a hard failure; the operator must commit the file before deploying.

### 3. Merge semantics
```
base  = config file key/value pairs
overlay = resolved type:env secrets (from Store.Resolve)
result = base merged with overlay (overlay wins on key collision)
```
For each key present in both base and overlay: log at Debug level `"config key overridden by secret"` with the key name (never the value). Write `result` to `env_file` via `compose.WriteEnvFile`.

If `stack.ConfigFile == ""` and there are `type:env` secrets: write only the secrets map (existing wu-16 behavior, unchanged).

If `stack.ConfigFile != ""` and there are no `type:env` secrets: write only the config file map.

### 4. Config file format
Parse line by line:
- Skip lines where the first non-space character is `#`.
- Skip blank lines.
- Split on the first `=`. Left side is the key (trimmed), right side is the value (trimmed). No shell variable expansion, no quote stripping — values are taken literally.
- Lines without `=` are ignored with a Debug-level warning.

## Constraints
- `go build ./...` must pass.
- Do not modify files outside the Modifies list.
- Stacks without `config:` behave identically to wu-16 — no regressions.
- Config file path must be within the IaC repo (`m.repoDir()`). Do not allow absolute paths or `..` traversal. Return an error if `stack.ConfigFile` is absolute or contains `..`.
- Do not write the config file values to the herald secrets store. They are plain config, not secrets.

## Failure Modes
- **Config file missing from IaC repo**: deploy fails before writing env_file. Detection: error message with file path. Fix: commit the config file.
- **Key collision silently drops config value**: overlay wins, but Debug log records it. Detection: check logs if a config value appears wrong at runtime.
- **Path traversal via `../`**: attacker-controlled config.yml could read arbitrary files. Detection: validate `stack.ConfigFile` contains no `..` components and is not absolute.

## Verification
```bash
go build ./...
go test ./internal/config/...
go test ./internal/stacks/...
```
Manual: create `stacks/mystack/config.dev.env` in the IaC repo with `FOO=bar`. Configure the stack with `config: stacks/mystack/config.dev.env` and one `type: env` secret targeting `FOO`. After `herald update`, verify the written env_file contains the secret value for `FOO` (overlay wins), not `bar`.
