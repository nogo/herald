# Add config file and env injection to apps

## Outcome
Apps with `type: env` secrets have those values available as environment variables inside containers, not just for compose-file variable substitution. Apps with `config: path/to/config.env` have that file's non-secret values merged with resolved secrets and injected into containers. Both work identically to how stacks work after wu-16 and wu-17.

## Values
1. Env vars reach containers — the generated env file must be referenced explicitly in the overlay's `env_file`, not rely on Docker Compose auto-loading.
2. Same config shape as stacks — `config:` and env injection work identically in both `apps:` and `stacks:`.
3. Backward compatibility — apps without `config:` and with no `type: env` secrets behave exactly as before.

## Context

### The current gap
`deployer.go` `Deploy()` (line 132–134) writes `type: env` secrets to `appDir/.env` via `compose.WriteEnvFile(appRoot, envVars)`. However, `runCompose()` (line 271–282) runs from `repoDir` (`appDir/repo`). Docker Compose determines the project directory from the first `-f` file's location, which may be `repoDir` or an absolute IaC path — neither is `appDir`. The generated `appDir/.env` is therefore never loaded by Docker Compose for container env vars; it is unreachable.

The overlay's `env_file` is only set if `app.EnvFile != ""` (line 217–219), which is the user's static pre-existing env file, not the herald-generated one.

**Fix**: always add `filepath.Join(appDir, ".env")` as the first entry in `svc.EnvFile` in the overlay, before any user-specified `app.EnvFile`. This is an absolute path, so it resolves correctly regardless of the compose or override file locations.

### The config gap
`config:` (ConfigFile field) was added to the `Stack` struct (wu-17) and is resolved in `stacks/manager.go`. It does not exist on the `App` struct. Apps need the same: load config file from IaC repo, merge with resolved `type: env` secrets, write the merged result to `appDir/.env`.

- `internal/config/config.go` — `App` struct (line 31–40). Add `ConfigFile string`. Validate in `validate()`: no absolute paths, no `..` components (same constraints as wu-17 for stacks).
- `internal/deployer/deployer.go` — `Deploy()` step 4 (line 132). Currently `compose.WriteEnvFile(appRoot, envVars)` writes only secret env vars. Extend to merge with config file values the same way stacks do: read config file from `filepath.Join(d.Config.Server.DataDir, "repo", app.ConfigFile)`, parse KEY=VALUE pairs, overlay `envVars` on top, write merged map.
- `internal/deployer/deployer.go` — `generateOverride()` (line 193). Change `svc.EnvFile` to always include `filepath.Join(appDir, ".env")` as the first entry. If `app.EnvFile != ""`, append it as a second entry.
- `internal/stacks/manager.go` — reference for the config file parsing and merge pattern implemented in wu-17. Reuse the same logic; do not duplicate it. Extract shared parsing to `internal/compose` or `internal/config` if needed, or replicate the pattern directly.
- `internal/config/config.go` — `Stack.ConfigFile` (added by wu-17) as reference for the field shape.

**Note**: The herald `DataDir` (path to `/etc/herald`) must be accessible from the deployer. Check how `d.Config` is currently used to find the IaC repo path. The stack manager uses `m.DataDir` and `m.repoDir()`. The deployer may need a similar field or can use the existing config to derive it. Read both `deployer.go` and `cmd/serve.go` or wherever `Deployer` is constructed to find how to access the IaC repo path.

## Requirements

### 1. Config struct
Add to `App`:
```go
ConfigFile string `yaml:"config,omitempty" json:"config,omitzero"`
```
Validate in `validate()`: if set, must not be absolute and must not contain `..`. Error: `app %q: config must be a relative path within the IaC repo, got %q`.

### 2. Config file merge in Deploy()
Replace step 4 (`compose.WriteEnvFile(appRoot, envVars)`) with:

```
if app.ConfigFile != "":
    read filepath.Join(iacRepoDir, app.ConfigFile)
    if not found: return error "config file %q not found in IaC repo"
    parse as KEY=VALUE (same format as wu-17: skip # comments, skip blank lines,
                        split on first =, trim key and value, no shell quoting)
    merged = configFileMap overlaid with envVars (envVars wins on collision)
    log Debug for each collision: "config key overridden by secret", key name only
else:
    merged = envVars
compose.WriteEnvFile(appRoot, merged)
```

### 3. Overlay env_file injection
In `generateOverride()`, change:
```go
if app.EnvFile != "" {
    svc.EnvFile = []string{app.EnvFile}
}
```
to:
```go
svc.EnvFile = []string{filepath.Join(appDir, ".env")}
if app.EnvFile != "" {
    svc.EnvFile = append(svc.EnvFile, app.EnvFile)
}
```
The herald-generated `.env` is always injected first. The user's static env file (if any) is appended.

### 4. IaC repo path in deployer
Determine how to resolve `iacRepoDir` (the path to the cloned IaC repo, e.g. `/etc/herald/repo`). Read how `Deployer` is constructed (likely in `cmd/serve.go` or `cmd/deploy.go`) and how `StackManager` accesses its `DataDir`. Add a `DataDir string` field to `Deployer` if not already present, set at construction time, and use `filepath.Join(d.DataDir, "repo")` to get the IaC repo path.

## Constraints
- `go build ./...` must pass.
- Do not modify files outside the Modifies list unless strictly required by requirement 4 (adding DataDir to Deployer construction site).
- Apps without `config:` and with no `type: env` secrets must write an empty (or minimal) `.env` to `appDir` and still include it in `svc.EnvFile`. An empty `env_file` entry is harmless.
- Never log secret values, only key names.
- Config file path must not escape the IaC repo: reject absolute paths and paths containing `..`.

## Failure Modes
- **Config file missing**: deploy fails before any file writes. Detection: error message with path.
- **type:env secrets not reaching containers (regression prevented)**: if `svc.EnvFile` is not set, secrets are invisible to the container. Detection: `docker inspect <container>` shows no `Env` entries for the secret keys.
- **DataDir wrong**: config file read from incorrect path. Detection: "config file not found" error even when file exists in IaC repo.
- **Duplicate env_file entries**: user sets `app.EnvFile` to the same path as `appDir/.env`. Results in duplicate entries; harmless but untidy. Out of scope.

## Verification

```bash
go build ./...
go test ./internal/config/...
go test ./internal/deployer/...
```
Manual: configure an app with one `type: env` secret and `config: path/to/file.env`. Deploy. Verify `appDir/.env` contains both config file values and secret value (secret wins on collision). Verify `docker inspect herald-<appname>_<service>` shows the env var from the secret in the container's `Env` array.
