# Tag deployment — config schema

## Outcome
`App` gains two optional fields: `tag` (static pin) and `tag_pattern` (glob for auto-deploy on tag push). `branch` becomes optional when `tag` is set. Validation enforces mutual exclusivity. All existing configs remain valid.

## Values
1. Explicit over magic — `tag:` and `branch:` are mutually exclusive, never inferred from each other.
2. Pattern syntax matches GitHub's — stdlib `path.Match` glob, same syntax users already know.

## Context
- `internal/config/config.go` — `App` struct, `validate()` function, default-applying loop.
- `branch` currently defaults to `"main"` for every app. That default must only apply when `tag` is absent.
- Validation currently requires `repo`, `branch`, `domain`. After this WU `branch` is required only when `tag` is absent.

## Creates
None.

## Modifies
internal/config/config.go

## Requirements

### 1. Add fields to `App`
```go
type App struct {
    Repo       string         `yaml:"repo"                  json:"repo"`
    Branch     string         `yaml:"branch,omitempty"      json:"branch,omitzero"`
    Tag        string         `yaml:"tag,omitempty"         json:"tag,omitzero"`
    TagPattern string         `yaml:"tag_pattern,omitempty" json:"tag_pattern,omitzero"`
    Domain     string         `yaml:"domain"                json:"domain"`
    EnvFile    string         `yaml:"env_file,omitempty"    json:"env_file,omitzero"`
    ConfigFile string         `yaml:"config,omitempty"      json:"config,omitzero"`
    Compose    string         `yaml:"compose,omitempty"     json:"compose,omitzero"`
    Override   string         `yaml:"override,omitempty"    json:"override,omitzero"`
    Secrets    []SecretRef    `yaml:"secrets,omitempty"     json:"secrets,omitzero"`
    Preview    *PreviewConfig `yaml:"preview,omitempty"     json:"preview,omitzero"`
}
```

### 2. Default `branch` only when `tag` is absent
In the defaults loop (currently sets `app.Branch = "main"` when empty):
```go
if app.Branch == "" && app.Tag == "" {
    app.Branch = "main"
}
```

### 3. Validation rules (add inside the apps loop in `validate`)
After checking `repo` and `domain`, add:

```go
// tag and branch are mutually exclusive
if app.Tag != "" && app.Branch != "" {
    return fmt.Errorf("app %q: tag and branch are mutually exclusive", name)
}
// one of tag or branch is required
if app.Tag == "" && app.Branch == "" {
    return fmt.Errorf("app %q: one of branch or tag is required", name)
}
// tag_pattern only valid alongside branch
if app.TagPattern != "" && app.Tag != "" {
    return fmt.Errorf("app %q: tag_pattern requires branch (not compatible with tag)", name)
}
// validate tag_pattern is a legal glob
if app.TagPattern != "" {
    if _, err := path.Match(app.TagPattern, ""); err != nil {
        return fmt.Errorf("app %q: tag_pattern %q is not a valid glob: %w", name, app.TagPattern, err)
    }
}
```

Add `"path"` to imports.

### 4. Existing validation order
Keep the existing checks for `repo`, `domain`, `config`, `secrets`, and `preview` — just insert the new rules after the `domain` duplicate check.

## Constraints
- `go build ./...` must pass.
- `go test ./...` must pass.
- Existing configs with only `branch:` set continue to work unchanged.
- A config with only `tag:` set (no `branch:`) must be valid.
- A config with both `branch:` and `tag_pattern:` must be valid.

```bash
go build ./...
go test ./...
```
