# Unify App and Service into Stack config type

## Outcome

The config file uses a single `stacks:` key. The Go type `Stack` replaces `App` and `Service`. `Config.Stacks` is the canonical field. `Config.Apps` and `Config.Services` remain as **read-only computed accessors** (methods, not fields) so all downstream packages continue to compile. Existing config tests are rewritten for the `stacks:` key. The entire project builds and all tests pass.

## Values

1. Build stays green — every package compiles after this WU. Accessor methods bridge the gap until downstream WUs migrate.
2. Clean break in config YAML — only `stacks:` is supported. No `apps:` or `services:` parsing.
3. One type, one field — `Config.Stacks map[string]Stack` is the source of truth.

## Context

- `docs/architecture.md` — "Domain Model" section: `repo:` and `path:` are mutually exclusive, everything else is shared.
- `internal/config/config.go` — `App` struct (lines 33-45), `Service` struct (lines 47-55), `Config` struct (lines 18-22), `validate()` (lines 146-251), `Load()` (lines 74-125). All replaced.
- `internal/config/config_test.go` — existing tests for config parsing and validation.
- Every package that references `Config.Apps` or `Config.Services` — these must keep compiling via accessor methods.

## Requirements

### 1. Stack type

Replace `App` and `Service` with a single `Stack` struct:

```go
type Stack struct {
    // Source (mutually exclusive)
    Repo   string `yaml:"repo,omitempty"   json:"repo,omitzero"`
    Path   string `yaml:"path,omitempty"   json:"path,omitzero"`

    // Git tracking (repo: stacks only)
    Branch     string `yaml:"branch,omitempty"      json:"branch,omitzero"`
    Tag        string `yaml:"tag,omitempty"          json:"tag,omitzero"`
    TagPattern string `yaml:"tag_pattern,omitempty"  json:"tag_pattern,omitzero"`

    // Routing
    Domain string `yaml:"domain" json:"domain"`

    // Compose
    Compose  string `yaml:"compose,omitempty"   json:"compose,omitzero"`
    Override string `yaml:"override,omitempty"  json:"override,omitzero"`

    // Environment
    EnvFile    string `yaml:"env_file,omitempty" json:"env_file,omitzero"`
    ConfigFile string `yaml:"config,omitempty"   json:"config,omitzero"`

    // Secrets
    Secrets []SecretRef `yaml:"secrets,omitempty" json:"secrets,omitzero"`

    // Preview (repo: stacks only)
    Preview *PreviewConfig `yaml:"preview,omitempty" json:"preview,omitzero"`

    // Path-stack specific
    AutoDeploy   bool   `yaml:"auto_deploy,omitempty"   json:"auto_deploy,omitzero"`
    UpdateScript string `yaml:"update,omitempty"         json:"update,omitzero"`
}
```

### 2. Config struct

```go
type Config struct {
    Server Server           `yaml:"server"            json:"server"`
    Stacks map[string]Stack `yaml:"stacks,omitempty"  json:"stacks,omitempty"`
}
```

### 3. Backwards-compatible accessor methods

Add these methods to `Config` so all downstream code compiles without changes:

```go
// Apps returns stacks that have a Repo set (backwards-compat accessor).
// Deprecated: use Config.Stacks directly. Will be removed.
func (c *Config) Apps() map[string]Stack {
    ...filter Stacks where Repo != ""...
}

// Services returns stacks that have a Path set (backwards-compat accessor).
// Deprecated: use Config.Stacks directly. Will be removed.
func (c *Config) Services() map[string]Stack {
    ...filter Stacks where Path != ""...
}
```

**Critical**: Since `Apps` and `Services` were previously fields (not methods), all downstream code accesses them as `Cfg.Apps` and `Cfg.Services` (no parentheses). This means methods won't work as a transparent bridge. Instead, keep them as computed fields populated by `Load()`:

```go
type Config struct {
    Server   Server           `yaml:"server"            json:"server"`
    Stacks   map[string]Stack `yaml:"stacks,omitempty"  json:"stacks,omitempty"`

    // Deprecated computed fields — populated by Load() from Stacks.
    // Will be removed once all downstream packages migrate to Stacks.
    Apps     map[string]Stack `yaml:"-" json:"-"`
    Services map[string]Stack `yaml:"-" json:"-"`
}
```

In `Load()`, after parsing and validation, populate `Apps` and `Services` by filtering `Stacks`:

```go
cfg.Apps = make(map[string]Stack)
cfg.Services = make(map[string]Stack)
for name, stack := range cfg.Stacks {
    if stack.Repo != "" {
        cfg.Apps[name] = stack
    }
    if stack.Path != "" {
        cfg.Services[name] = stack
    }
}
```

This means `Cfg.Apps["myapp"]` returns a `Stack` (not the old `App` type). Since `Stack` contains all fields from both `App` and `Service`, downstream code that accesses `app.Repo`, `app.Branch`, `app.Domain`, `app.Secrets`, etc. will compile because those fields exist on `Stack`. The old `App.ConfigFile` was `yaml:"config"` — `Stack` uses the same field name `ConfigFile`, so field access is compatible. The old `Service.UpdateScript` was `yaml:"update_script"` — `Stack` uses `UpdateScript` with `yaml:"update"`, so Go field access is compatible but the YAML key changes (which is fine since we're doing a clean config break).

### 4. Type alias for downstream compat

The old code uses `config.App` and `config.Service` types in function signatures and struct fields. Add type aliases:

```go
// Deprecated: use Stack directly.
type App = Stack
type Service = Stack
```

These are type aliases (not new types), so `config.App` and `config.Stack` are interchangeable. This ensures that code like `func deploy(app config.App)` continues to compile.

### 5. Defaults in Load()

- If `Repo` is set and both `Branch` and `Tag` are empty: default `Branch` to `"main"`.
- If `Repo` is set and `Compose` is empty: default `Compose` to `"compose.yml"`.
- `Path` stacks get no branch/tag/compose defaults.

### 6. Validation

One loop over `Stacks`. For each stack:

- `repo` and `path` are mutually exclusive. Exactly one must be set.
- `domain` is required. Domain uniqueness check across all stacks.
- Secret type validation (same as current).
- If `repo` is set:
  - Validate repo format (`owner/name`).
  - `tag` and `branch` mutually exclusive; one required.
  - `tag_pattern` requires `branch`.
  - `config` must be relative, no `..`.
  - Preview validation (domain required if enabled, must contain `*`).
- If `path` is set:
  - `branch`, `tag`, `tag_pattern`, `preview` are invalid — error if set.
  - `compose` and `override` are invalid — error if set.
  - `auto_deploy` and `update` are allowed.

### 7. Tests

Rewrite config tests for `stacks:` key:
- Parse minimal repo stack (defaults applied).
- Parse minimal path stack.
- Parse full repo stack with all fields.
- Parse full path stack with all fields.
- Validation: missing domain, missing repo+path, both repo+path set, duplicate domains.
- Validation: path stack with branch/tag/preview/compose/override set (must error).
- Validation: tag/branch exclusivity, tag_pattern constraints.
- Validation: secret type and generate constraints.
- Env var expansion in github_token.
- Default port and acme_email.
- Verify `Apps` and `Services` computed fields are correctly populated.

## Constraints

- `mise run check` must pass (full project build, all tests).
- `SecretRef` and `PreviewConfig` types are unchanged.
- `Server` type is unchanged (including `ServicesDir` field name).
- Type aliases `App = Stack` and `Service = Stack` ensure downstream type compatibility.
- Computed fields `Apps` and `Services` ensure downstream field access compatibility.

## Failure Modes

- **Field name mismatch**: `Stack` uses different field names than old `App`/`Service`. Detection: compile error in downstream packages. Mitigation: verify field names match (Repo, Branch, Tag, TagPattern, Domain, Compose, Override, EnvFile, ConfigFile, Secrets, Preview, Path, AutoDeploy, UpdateScript).
- **Missing yaml tag compat**: Old `Service.UpdateScript` had `yaml:"update_script"`. New `Stack.UpdateScript` has `yaml:"update"`. This only matters for YAML parsing (clean break), not Go field access. But if any test YAML uses `update_script:`, it will silently not parse. Detection: test that `update:` key works.
- **Computed field not populated**: `Apps`/`Services` maps are nil if `Load()` doesn't populate them. Detection: downstream code panics on nil map access. Mitigation: always initialize to empty map.
