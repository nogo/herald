# [gate] Stack config parsing and validation tests

## Outcome

Comprehensive test coverage for the unified `Stack` config type. Tests exercise every validation rule, default application, edge case, and error path. All tests pass. The config package is a solid foundation for the remaining WUs.

## Values

1. Coverage over speed — every validation branch must have a test.
2. Table-driven tests — easy to add new cases as the config evolves.
3. Tests document the contract — reading the test file tells you what config is valid.

## Context

- `internal/config/config.go` — the `Stack` type, `Load()`, and `validate()` as modified by wu-28.
- `internal/config/config_test.go` — tests as modified by wu-28. This gate WU adds coverage for any gaps.
- `docs/architecture.md` — "Domain Model" section: `repo:` and `path:` are mutually exclusive.

## Creates

None.

## Modifies

internal/config/config_test.go

## Requirements

### 1. Round-trip parsing tests

Test that a config YAML with `stacks:` key parses correctly and all fields are populated:
- Repo stack with branch, tag_pattern, secrets, preview, config, override, env_file.
- Path stack with auto_deploy, update, secrets, config, env_file.
- Mixed config with both repo and path stacks.

### 2. Default application tests

- Repo stack with no branch/tag gets `branch: main`.
- Repo stack with no compose gets `compose: compose.yml`.
- Path stack gets no branch or compose defaults.
- Server with no port gets `9483`.
- Server with no acme_email gets `webmaster@<deploy_domain>`.

### 3. Validation error tests (table-driven)

Each case provides invalid YAML and asserts a specific error substring:
- Missing `server.name`, `server.deploy_domain`, `server.services_dir`.
- Stack missing both `repo` and `path`.
- Stack with both `repo` and `path`.
- Stack missing `domain`.
- Duplicate domains across stacks.
- Invalid repo format.
- `tag` and `branch` both set.
- Neither `tag` nor `branch` on repo stack.
- `tag_pattern` with `tag` (not `branch`).
- Invalid `tag_pattern` glob.
- `config` with absolute path or `..` traversal.
- Invalid secret type (not `env` or `docker-secret`).
- Invalid `generate` value.
- `length` without `generate`.
- `length` out of range.
- Path stack with `branch` set.
- Path stack with `tag` set.
- Path stack with `preview` set.
- Path stack with `compose` set.
- Path stack with `override` set.
- Preview enabled without domain.
- Preview domain without wildcard.

### 4. Edge cases

- Empty `stacks:` map (valid — no stacks configured).
- Stack name with hyphens and underscores (valid).
- `github_token` env var expansion.

## Constraints

- `mise run check` must pass.
- Do not modify `config.go` — this is a test-only WU.
- Tests must not depend on filesystem state (use `os.CreateTemp` for YAML files).

## Failure Modes

- **Missing validation test**: A future WU introduces invalid config that isn't caught. Detection: review test table against validation function branches.
- **False positive test**: Test passes but doesn't actually exercise the error path. Detection: temporarily comment out the validation rule and verify the test fails.
