# Unify deployer for repo and path stacks

## Outcome

`deployer.Deployer.Deploy()` handles both `repo:` stacks (git clone from GitHub) and `path:` stacks (symlink to IaC repo directory). The source resolution step is a fork based on `stack.Repo != ""` vs `stack.Path != ""`. Everything downstream (secrets, env, override, compose up, post-deploy hook) is one code path. `ServiceManager.ComposeUp()` and `ServiceManager.Update()` logic is absorbed into the deployer.

## Values

1. One deploy path — no code duplication for the deploy pipeline.
2. `path:` stacks use symlink + compose up, same as current service behavior.
3. `update:` script runs as a post-deploy hook after compose up, not instead of it.
4. Deploy dir is flat: `<services_dir>/<name>/` for all stacks.

## Requirements

### 1. Unified Deploy()

`Deploy(ctx, stackName, ref)` does:

1. Look up `stack` from `Config.Stacks[stackName]`.
2. **Source resolution** (the only fork):
   - If `stack.Repo != ""`: git clone/fetch to `<deployDir>/repo/` (existing `gitSync` logic).
   - If `stack.Path != ""`: create `<deployDir>/repo` symlink pointing to `<iacRepoDir>/<stack.Path>`. Verify the target path exists. If symlink already exists and points to the right place, skip.
3. **Preflight**: check missing secrets.
4. **Secrets**: resolve, write env file, write docker secrets.
5. **Override**: generate compose.override.yml using `GenerateOverride`. Default port is `"3000"` for repo stacks, `"80"` for path stacks.
6. **Caddy network**: ensure exists.
7. **Compose up**: `docker compose up -d --build --remove-orphans`.
8. **Post-deploy hook**: if `stack.UpdateScript != ""`, run it (absorb `RunUpdateScript` logic from ServiceManager). The script receives env vars: `STACK_NAME`, `STACK_DIR`, `STACK_DOMAIN`, `COMPOSE_FILE`, `COMPOSE_OVERRIDE_FILE`.
9. **Deployed ref**: write `deployed_ref` file for repo stacks only.

### 2. Deploy dir

All stacks use `filepath.Join(Config.Server.ServicesDir, stackName)` as the deploy directory. No `apps/` or `services/` subdirectory.

### 3. Docker project name

All stacks use `"herald-" + stackName` as the Docker Compose project name. No `herald-svc-` prefix.

### 4. Compose context unification

In `compose/context.go`:
- Replace `ResolveApp()` and `ResolveService()` with a single `ResolveStack(cfg *config.Config, stackName string) (*Context, error)`.
- `ResolveStack` builds the context from `Config.Stacks[stackName]`, using the flat deploy dir and uniform project name.
- `Resolve()` tries stacks first, then previews. No three-way dispatch.
- Delete `ResolveApp()` and `ResolveService()`.

### 5. Down()

`Down()` looks up the stack from `Config.Stacks` (not `Config.Apps`). Uses `ResolveStack` for compose context.

### 6. DeployAsync and per-stack locking

Keep the existing `DeployAsync` with per-stack locking and drop semantics. Works identically for both repo and path stacks.

### 7. IaC repo git pull for path stacks

For `path:` stacks, `Deploy()` does NOT pull the IaC repo. That's the responsibility of `herald sync` or the IaC push webhook handler. Deploy just uses whatever is currently on disk.

### 8. RunUpdateScript as post-deploy hook

Move `RunUpdateScript` logic from `ServiceManager` into `Deployer` as a private method `runPostDeployHook()`. It runs only when `stack.UpdateScript != ""`. The script path is resolved relative to the IaC repo root: `filepath.Join(dataDir, "repo", stack.UpdateScript)`.

### 9. Tests

- Test that `Deploy` with a `path:` stack creates the symlink correctly (mock or skip actual compose up).
- Test that `Deploy` with a `repo:` stack calls git sync (mock or skip actual git operations).
- Test `ResolveStack` returns correct paths for both stack types.
- Test `Down` resolves the correct compose context.

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- `DeployAsync` goroutine and locking semantics are unchanged.
- The `runCompose` method must use `runner.RunCmdStream` for CLI UI streaming (not the old `runStreamCmd` from services).

## Failure Modes

- **Symlink target doesn't exist**: `path:` stack with wrong `path` value. Detection: `Deploy` returns error with "not found in IaC repo" message. Test this case.
- **Stale symlink**: IaC repo path changes but old symlink remains. Detection: `Deploy` should verify symlink target matches and recreate if needed.
- **Post-deploy hook runs before compose up**: Script expects running containers. Detection: ordering test or code review of step sequence.
- **Import cycle**: `deployer` importing `services`. Detection: `go build` fails. Mitigation: all logic moves INTO deployer, services is not imported.
