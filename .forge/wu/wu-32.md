# [gate] Unified deploy pipeline tests

## Outcome

Integration-level tests verify that the unified deployer correctly handles both `repo:` and `path:` stacks through the full pipeline: source resolution, secrets, env file, override generation, and compose context. Tests cover the critical path differences between the two stack types without requiring Docker or network access.

## Values

1. Test the pipeline, not the tools — mock Docker/git, test herald's orchestration logic.
2. Cover the fork — every test that matters runs for both `repo:` and `path:` stacks.
3. Regression prevention — these tests catch if the pipeline diverges again.

## Context

- `internal/deployer/deployer.go` — unified `Deploy()` from wu-31.
- `internal/deployer/helpers.go` — shared helpers from wu-30.
- `internal/deployer/helpers_test.go` — unit tests from wu-30.
- `internal/compose/context.go` — unified `ResolveStack()` from wu-31.
- `internal/config/config.go` — `Stack` type from wu-28.

## Creates

- `internal/deployer/deployer_test.go` — integration tests for the deploy pipeline.
- `internal/compose/context_test.go` — tests for `ResolveStack` and `Resolve` (if not already covered).

## Modifies

None. This is a test-only gate WU.

## Requirements

### 1. Deploy dir resolution tests

For both `repo:` and `path:` stacks, verify:
- Deploy dir is `<services_dir>/<stackName>/` (flat, no subdirectories).
- Docker project name is `herald-<stackName>`.

### 2. Source resolution tests

- `repo:` stack: verify `gitSync` is called with correct repo URL and ref.
- `path:` stack: verify symlink is created at `<deployDir>/repo` pointing to `<iacRepoDir>/<stack.Path>`.
- `path:` stack with missing target: verify error message.
- `path:` stack with stale symlink: verify it's recreated.

### 3. Override generation tests

- `repo:` stack: default port `3000`, env_file includes `<deployDir>/.env`.
- `path:` stack: default port `80`, env_file handling matches path stack config.
- Both: caddy labels, internal network, docker secrets in override.
- Inline `override:` YAML merges correctly with `DeepMergeYAML` (preserves `!override` tags).

### 4. Compose context tests (context_test.go)

- `ResolveStack` returns correct project name, compose file path, override file path, env file path, work dir for both stack types.
- `Resolve` finds stacks before previews.
- `Resolve` returns error for unknown names.

### 5. Post-deploy hook tests

- Stack with `update:` script: verify the script path, env vars (`STACK_NAME`, `STACK_DIR`, `STACK_DOMAIN`, `COMPOSE_FILE`, `COMPOSE_OVERRIDE_FILE`), and execution order (after compose up).
- Stack without `update:`: verify no script execution.

## Constraints

- `mise run check` must pass.
- Tests must not require Docker daemon, network access, or git remotes.
- Use `t.TempDir()` for filesystem state.
- Do not modify non-test files.

## Failure Modes

- **Tests pass but don't exercise the fork**: Both stack types go through the same mock path. Detection: temporarily break path-stack-specific logic and verify a test fails.
- **Flaky tests from temp dir cleanup**: Detection: run with `-count=5`.

## Verification

```bash
mise run check
```
