# Update webhook and serve for unified stacks

## Outcome

The webhook server and daemon (`herald serve`) use `Config.Stacks` instead of `Config.Apps` and `Config.Services`. The IaC push handler uses the deployer directly (not ServiceManager). Webhook matching logic works for all stacks with `repo:` set. Auto-deploy on IaC push works for `path:` stacks with `auto_deploy: true`. Preview routing works unchanged.

## Values

1. One deployer instance — `serve` creates one `deployer.Deployer`, not a deployer + ServiceManager.
2. Webhook matching unchanged — repo+branch matching, tag pattern matching, preview routing all work the same.
3. Auto-deploy via deployer — IaC push triggers `Deployer.DeployAsync` for path stacks with `auto_deploy: true`.

## Context

- `cmd/serve.go` — creates `deployer.Deployer`, `services.ServiceManager`, `preview.PreviewManager`, wires `OnDeploy`, `OnIaCPush`, `OnPreviewDeploy`, `OnPreviewTeardown`. Lines 49-117.
- `cmd/serve.go` — `makeIaCPushHandler()` (lines 188-226): pulls IaC repo, reloads config, loops services with auto_deploy. Must loop stacks instead.
- `internal/webhook/server.go` — `Server` struct, `handleWebhook()`, `handleTagPush()`, `handlePreviewEvent()`. These reference `Config.Apps`. Must reference `Config.Stacks` but only match stacks with `Repo` set.
- `internal/webhook/server.go` — `DeployRequest` struct (line 61-70): has `App config.App` field. Change to `Stack config.Stack`.
- `internal/webhook/server_test.go` — existing tests. Must be updated for `Stacks`.

## Requirements

### 1. serve.go

- Remove `ServiceManager` construction. Only create a `deployer.Deployer`.
- `OnDeploy`: calls `d.DeployAsync(req.StackName, req.Ref)` (same as now, field name change).
- `OnIaCPush`: `makeIaCPushHandler` takes `*deployer.Deployer` instead of `*services.ServiceManager`. It pulls the IaC repo, reloads config, updates `d.Config`, then loops `Config.Stacks` — for any stack with `Path != ""` and `AutoDeploy == true`, calls `d.DeployAsync(name, "")`.
- `OnPreviewDeploy` and `OnPreviewTeardown`: unchanged (still use PreviewManager).
- Remove `import "github.com/nogo/herald/internal/services"`.

### 2. webhook/server.go

- `Server.Config` references `Config.Stacks` in all matching logic.
- `DeployRequest.App` becomes `DeployRequest.Stack` with type `config.Stack`.
- `handleWebhook()`: iterate `Config.Stacks` instead of `Config.Apps`. Only match stacks where `stack.Repo == repo && stack.Branch == branch` (skip path stacks — they have no `Repo`).
- `handleTagPush()`: iterate `Config.Stacks`, skip those without `Repo` or `TagPattern`.
- `handlePreviewEvent()`: iterate `Config.Stacks`, check `stack.Preview` and `stack.Repo` (previews only work for repo stacks).
- `DeployRequest.AppName` becomes `DeployRequest.StackName`.

### 3. webhook/server_test.go

Update all test cases:
- Config fixtures use `Stacks` instead of `Apps`.
- `DeployRequest` assertions use `StackName` and `Stack`.
- Test that path stacks are never matched by webhook (no `Repo` field).

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- Webhook HMAC verification, rate limiting, and payload parsing are unchanged.
- Preview logic is unchanged in this WU (wu-37 handles preview).

## Failure Modes

- **Path stack matched by webhook**: A `path:` stack with no `Repo` is somehow matched. Detection: test that webhook with a repo matching nothing doesn't trigger path stacks.
- **Auto-deploy broken**: IaC push no longer triggers path stack deploys. Detection: test `makeIaCPushHandler` with a config containing auto_deploy path stacks.
- **Config reload race**: `makeIaCPushHandler` updates `Cfg` and `d.Config` without locking. This is the existing behavior — don't make it worse, but don't fix it in this WU either.
