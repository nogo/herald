# Update status and sync for unified stacks

## Outcome

`herald status` and `herald sync` display and reconcile stacks as a single list instead of separate "Apps" and "Services" sections. The status collector uses `Config.Stacks`. Sync checks all stacks in one loop. The `init` bootstrap creates a flat deploy directory structure.

## Values

1. Unified display — one "Stacks" section in status output, not "Apps" + "Services".
2. Sync treats all stacks uniformly — secret checks, deploy state, orphan detection.
3. No ServiceManager references remain in any `cmd/` file.

## Context

- `cmd/status.go` — constructs `StatusCollector`, prints apps and services separately (lines 108-155). Must print one "Stacks" section.
- `cmd/sync.go` — separate loops for apps (lines 113-166) and services (lines 170-203), orphan detection with `herald-` and `herald-svc-` prefixes (lines 280-318). Must be one loop, one prefix.
- `internal/status/collector.go` — `StatusCollector`, `ServerStatus` (has `Apps []AppStatus` and `Stacks []StackStatus` fields), `Collect()` method. Must unify into one `Stacks []StackStatus` field.
- `internal/status/collector_test.go` — existing tests. Must be updated.
- `internal/init/bootstrap.go` — creates `apps/` and `services/` directories under `services_dir`. Must create flat structure.
- `cmd/init.go` — references bootstrap. May reference App/Service types.

## Requirements

### 1. status/collector.go

- `ServerStatus`: remove `Apps []AppStatus`. Keep `Stacks []StackStatus` as the single list.
- `StackStatus` gets additional fields from `AppStatus`: `DeployedRef`, `LastCommit`. These are populated for repo stacks, empty for path stacks.
- Add a `Source` field to `StackStatus`: `"repo"` or `"path"` — useful for display.
- `Collect()`: one loop over `Config.Stacks`. For each stack:
  - Deploy dir: `<services_dir>/<name>/`
  - Docker project: `herald-<name>`
  - If repo stack: read `deployed_ref`, check container state.
  - If path stack: check container state only (no deployed_ref).

### 2. cmd/status.go

- One "Stacks" section replacing "Apps" and "Services".
- Table columns: Name, Domain, Status, Containers, Source, Ref.
- `Ref` column shows deployed ref for repo stacks, `-` for path stacks.
- `Source` column shows `repo` or `path`.

### 3. cmd/sync.go

- Remove `ServiceManager` construction and all `services` imports.
- One loop over `Config.Stacks` replacing separate app/service loops.
- For repo stacks: check deploy state, compare local vs remote HEAD.
- For path stacks: check if deploy dir exists and is set up.
- Orphan detection: known projects are `herald-<name>` for all stacks. Remove `herald-svc-` prefix logic.
- Secret warning: one loop over all stacks, same check.

### 4. init/bootstrap.go

- Create `<services_dir>/` base directory.
- Do NOT create `apps/` or `services/` subdirectories.
- Create `<services_dir>/previews/` for preview environments.
- Create `<services_dir>/caddy/` for caddy.
- Clone app repos into `<services_dir>/<name>/repo/` (flat path).

### 5. Tests

- Update `collector_test.go` for unified `Stacks` field in `ServerStatus`.
- Test that both repo and path stacks appear in the `Stacks` list with correct `Source` value.

## Constraints

- `mise run check` must pass.
- Do not modify files outside the Modifies list.
- The `web` package (`internal/web/handler.go`) likely references `ServerStatus.Apps` and `ServerStatus.Stacks` — check and update if needed. If it does, add `internal/web/handler.go` and its test file to the Modifies list.

## Failure Modes

- **Status JSON format changes**: External consumers of `herald status --json` see different field names. This is a clean break — acceptable.
- **Orphan false positives**: Old `herald-svc-<name>` projects reported as orphans after migration. Expected behavior — operator tears down old containers manually.
- **Bootstrap creates wrong dirs**: New deploys go to wrong location. Detection: test bootstrap output paths.
