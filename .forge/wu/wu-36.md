# [gate] CLI and webhook integration tests

## Outcome

Integration tests verify that the CLI commands, webhook handler, and status collector work correctly with the unified stack model. Tests cover the full request path from webhook payload to deploy dispatch, and from config to status output. All existing tests pass with the new types.

## Values

1. End-to-end paths — test webhook → matching → deploy dispatch for both repo and path stacks.
2. Regression coverage — no test references `Config.Apps`, `Config.Services`, `AppStatus`, or `ServiceManager`.
3. Negative tests — verify path stacks are invisible to webhooks, repo stacks ignore auto_deploy.

## Context

- `internal/webhook/server.go` and `server_test.go` — webhook matching with `Config.Stacks` from wu-34.
- `internal/status/collector.go` and `collector_test.go` — unified status from wu-35.
- `cmd/deploy.go`, `cmd/down.go`, `cmd/sync.go` — CLI commands from wu-33 and wu-35.
- `internal/compose/context.go` and `context_test.go` — `ResolveStack` from wu-31.

## Creates

None. This gate adds tests to existing test files.

## Modifies

internal/webhook/server_test.go
internal/status/collector_test.go
internal/compose/context_test.go

## Requirements

### 1. Webhook matching tests

- Repo stack: push to matching repo+branch triggers deploy with correct `StackName` and `Ref`.
- Repo stack: push to non-matching branch is ignored.
- Path stack: push to any repo does NOT match (path stacks have no `Repo`).
- Tag push: matches stacks with `TagPattern`, dispatches with `refs/tags/<tag>` ref.
- IaC repo push: verify the event is recognized (test `OnIaCPush` callback is invoked).
- Preview: push to non-default branch on preview-enabled repo stack triggers preview deploy.
- HMAC signature: invalid signature rejected, valid signature accepted.

### 2. Status collector tests

- Config with repo stacks: status shows `Source: "repo"`, `DeployedRef` populated.
- Config with path stacks: status shows `Source: "path"`, `DeployedRef` empty.
- Mixed config: both types appear in one `Stacks` list, sorted by name.
- Empty config: no stacks listed, no error.

### 3. Compose context tests

- `ResolveStack` for repo stack: project name `herald-<name>`, compose file in `<name>/repo/<compose>`.
- `ResolveStack` for path stack: project name `herald-<name>`, compose file found via `FindComposeFile`.
- `Resolve` returns stack before preview when both match.
- `Resolve` returns error for unknown name.

### 4. Grep for old types

As a final check, grep for `ServiceManager`, `AppStatus`, `ResolveApp`, `ResolveService` in non-test source. These should not appear. Note: `Config.Apps` and `Config.Services` still exist as deprecated computed fields (removed in wu-38) — they are allowed in `config.go` only.

## Constraints

- `mise run check` must pass.
- Do not modify non-test files.
- Tests must not require Docker daemon or network access.

## Failure Modes

- **Stale test fixture**: Test config still uses `apps:` key. Detection: config parsing fails (wu-28 removed `apps:` support).
- **Missing import update**: Test file still imports `services` package. Detection: compile error.
