# [gate] Final system verification

## Outcome

The entire codebase compiles, all tests pass, documentation is consistent, and no references to the old `apps:`/`services:` model remain in source code or docs. The `.forge/verify` boundary checks pass. The refactoring is complete.

## Values

1. Completeness — zero remnants of the old model.
2. Consistency — docs, code, tests, and config examples all use the same terminology.
3. Green build — `mise run check` and `.forge/verify` both exit 0.

## Context

- All files modified by wu-28 through wu-39.
- `docs/architecture.md`, `docs/project.md`, `docs/config.md`, `README.md`.
- `.forge/verify` — boundary import checks.
- `.forge/context.md` — architectural invariants.

## Creates

None.

## Modifies

(Any file that needs a fix to pass verification. This gate WU is authorized to make surgical fixes across the codebase.)

## Requirements

### 1. Full build and test

Run `mise run check`. All tasks must pass: vet, fmt:check, tidy, test, lint.

### 2. Boundary verification

Run `.forge/verify`. The supporting package boundary check must pass.

### 3. Terminology grep

Verify no stale references remain in source code:

```bash
# No old config field references in non-test Go code:
grep -rn 'Config\.Apps\b\|Config\.Services\b' --include='*.go' internal/ cmd/
# No old type references:
grep -rn 'ServiceManager\|ServiceInfo\|AppStatus\b' --include='*.go' internal/ cmd/
# No old compose context functions:
grep -rn 'ResolveApp\b\|ResolveService\b' --include='*.go' internal/ cmd/
# No old package imports:
grep -rn 'internal/services' --include='*.go' internal/ cmd/
```

All of the above must return zero results.

### 4. Documentation grep

```bash
# No old config keys in docs:
grep -n '^apps:\|^services:' README.md docs/config.md
# No deleted commands:
grep -n 'herald update\|herald logs\|herald exec' README.md docs/config.md
# No old file paths:
grep -n 'apps/<name>\|services/<name>\|herald-svc-' README.md docs/config.md docs/architecture.md
```

All of the above must return zero results.

### 5. Fix any issues

If any check fails, make the minimal fix. Common expected issues:
- A test file still references old types → update the test.
- A doc still mentions the old model → update the doc.
- An import is unused after migration → remove it.
- `gofmt` needed → run `gofmt -w .`.

## Constraints

- `mise run check` must pass.
- `.forge/verify` must pass.
- Fixes must be minimal — do not refactor or add features. Only fix what's broken.
- If a fix requires more than 20 lines of changes to a single file, flag it as an incomplete migration from a prior WU.

## Failure Modes

- **Incomplete prior WU**: A significant piece of logic was missed by wu-28–39. Detection: compile error or test failure that requires substantial new code. Resolution: the gate WU's repair loop should handle it, but if it exceeds 3 attempts, manual intervention is needed.
- **Flaky test**: A test passes locally but fails in CI-like conditions. Detection: run with `-count=3`.

mise run check
